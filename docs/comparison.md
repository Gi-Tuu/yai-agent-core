## 1. 一句话定位（按类别）

| 方案 | 定位 | 形态 |
|---|---|---|
| **YAI Agent Core（本项目）** | 进程内嵌入式、自适应的 Agent **内核**：宿主只声明能力，内核自动发现工具、自适应路由并执行 | Python 库（`pip install`），内核本体零第三方硬依赖 |
| 通用 Agent 框架（一类） | 提供工具抽象、链式组合与中间件，开发者自行拼装出 Agent | Python/JS 库或框架 |
| 低层图编排运行时（一类） | 把 Agent 表达成节点/边与状态机，强调精确控制与长运行流程 | Python/JS 框架 |
| 多智能体框架（一类） | 以"角色 + 协作/对话"为第一抽象，编排多个 Agent 分工 | Python 框架 |
| 自托管 LLM 应用平台（一类） | 服务端平台提供可视化编排、插件市场与运维面板，应用作为调用方接入 | 自托管平台（服务端 + Web 控制台） |
| 托管无代码平台（一类） | 网页上拖拽配置 Bot/工作流，运行与运营都在平台内 | 托管 SaaS |

## 2. 关键维度对比

| 维度 | YAI Agent Core | 通用框架 / 图编排 | 多智能体框架 | 自托管平台 | 托管无代码平台 |
|---|---|---|---|---|---|
| 交付形态 | 被 import 的库，随宿主进程运行 | 库/框架 | 库/框架 | 自托管服务端平台 | 托管 SaaS |
| 开发者要做什么 | 写普通业务函数并声明能力；**不写 Agent Loop/Planner/工具选择** | 自己定义 agent、工具、链/图、状态与边 | 自己定义角色、任务、协作流程 | 在平台里配置提示词、工具、工作流 | 网页上拖拽配置 Bot/插件 |

| 内核运行时依赖 | **`dependencies = []`**（openai/fastapi/mcp/httpx 均为可选 extra 且懒加载） | 一组分层依赖包 | 框架依赖 | 完整服务端栈（多容器编排） | 无（平台托管） |

## 3. YAI 的差异化主张（对应"技术创新"评分）

1. **范式反转：从"拼装框架"到"嵌入式内核"。** 现有框架的共同前提是"开发者先有一个 Agent 要做，再去定义它"；YAI 回答的是另一个问题——"一个已经存在的软件（笔记、CRM、陪伴 App……）如何不写 Agent 代码就获得 Agent 能力"。类比不是 ORM，而是嵌入式数据库：能力像数据一样长在应用里。
2. **能力自发现而非手工注册。** 宿主普通 Python 函数经 type hints + docstring 自动生成 JSON Schema 工具；外部 MCP Server 与 OpenAPI 服务同构接入，执行侧零感知。
3. **自适应路由 + 能力缺口闭环。** 内核按任务在 direct/react/plan/clarify 间选择（规则零成本兜底、LLM 增强、决策来源可审计）；当工具不足以完成任务时，先发出 `capability_missing` 事件，若注入了 `ToolDiscovery` 发现源则在本轮把缺失能力发现、注册并调用（发 `tool_discovered` 事件，发现≠授权）——把"我缺什么能力"从一句提示变成可运行的闭环，而不是假装工具存在或盲目调用。
4. **路由会从反馈里自校准（self-adaptive 坐实）。** 关键词/LLM 路由是开环的，判一次就结束；YAI 可选地在任务结束后从事件流抽取成败，按任务特征分桶累计 Beta(α,β) 后验，用 Thompson Sampling 为同类任务调整策略，冷启动确定性跟随规则、有真实反馈后才采样。纯标准库、零依赖、离线可复现：内置 benchmark 五线（含"无先验""无上下文"消融）显示末段成功率 89.6% vs 规则 73.3%。学习默认关闭、硬规则区域不表态，学习算法本身也是第七个 SPI（`RouteSelector`）可替换。
5. **内核零硬依赖 + SPI 十契约。** 内核本体 `dependencies = []`，模型/通道/记忆/权限/发现源/沙箱/路由学习/文本嵌入/存储加密/资源访问全部可替换；这让内核可以进入移动端、桌面端、受限网络等装不下框架全家桶的环境。
6. **工具发现是"双通道"而非关键词。** 关键词匹配召不回"出门该怎么穿、要不要带外套"这类没有"天气"字样的缺口；YAI 的 `SemanticCatalog` 用词法（零依赖、永远可用）+ 可选 embedding 语义两条独立通道召回，余弦用标准库 `math` 计算（不引 numpy 进内核），并用"绝对门槛 + 多候选 top1 边际"避免在一堆相似候选里误召回；嵌入后端可插拔（本地离线免费，或云端兼容接口），不配置或报错自动降级纯词法。阈值用真实本地模型校准而非拍脑袋。

## 4. 什么场景该选哪一类（诚实建议）

- 你要**可视化拖拽、让非技术同学搭 Bot/知识库** → 选**自托管平台**或**托管无代码平台**那一类，这是它们的主场，YAI 不竞争。
- 你要**多角色分工、多智能体协作** → 选**多智能体框架**那一类，YAI 明确不做多智能体。
- 你要**精细的图编排、长运行有状态流程、人工审批节点** → 选**低层图编排运行时**那一类。
- 你要**最丰富的现成集成数量、快速拼装原型** → 选**通用 Agent 框架**那一类。
- 你要**把 Agent 能力内嵌进一个已有软件、保持进程内运行、不引入平台、不自己写 Agent 循环** → 这正是 **YAI Agent Core** 的位置。
