# YAI Agent Core v0.13.0

> 发布日期：2026-10-22 · 范围：`v0.12.0` 之后的 PR（#74、#75）· 许可证：MIT
> 本页是 GitHub Release 正文源稿；逐条变更清单以 [`CHANGELOG.md`](https://github.com/Gi-Tuu/yai-agent-core/blob/main/CHANGELOG.md) 的 `[v0.13.0]` 小节为准。

**这一版的主线：把"还差点"的五处补到能上线，并把"外部契约声明"收紧成"内核原生强制"。**

五处"还差点"都是同一类病：**看起来有护栏，实际没生效**——条件永远不命中、前缀等于整个根目录、结果绕过了入参那一侧的脱敏。另一批是**从外部契约到内核原生**的收紧：声明里的执行提示此前只解析不执行，现在真的被执行。

**没有破坏性变更**：新增能力一律 opt-in；多模态默认关闭（`parts=None`，输出逐字不变）；既有宿主零改动。

## 一、入参校验：schema 子集从 4 个关键字扩到 13 个

此前按绑定 schema 校验调用值只看**结构**（`type` / `required` / `properties` / `items`），**取值域**一律不看。后果很具体：声明写 `{"amount": {"type": "number", "minimum": 100}}`，调用传 `amount=1` 照样通过"类型对、数值离谱"的入参。

现在支持 `enum` / `pattern` / `minimum` / `maximum` / `minLength` / `maxLength` / `minItems` / `maxItems` / `format`（只实现 `date-time` 与 `date` 两种——能可靠判定的那两种）。

三条口径：

- **`enum` 用严格 JSON 相等**：`"1" != 1`、`True != 1`。不为了"宽容"做跨类型相等——那等于给"参数写成字符串"开一条绕过门槛的路。
- **`pattern` 用 `re.search`**（JSON Schema 语义是部分匹配）；**模式本身非法时跳过**（声明写错不该让业务操作被拦），但也不假装校验过。
- **仍未实现、记录在册**：`anyOf` / `oneOf` / `allOf` / `$ref` / `additionalProperties` / `exclusive*` / `multipleOf` / `uniqueItems` / `const`。范围是**故意有限**的：多实现几个键就多几分"看起来很严"，但没实现的键会让人误以为已经校验过。

## 二、多模态：从"能塞图片"到"能上线"

### 2.1 预算口径：图片不再"不占预算"

此前上下文预算按**渲染文本长度**计——图片渲染成一句占位，长度几十字符，于是"塞 50 张图"在预算上几乎免费。现在图片按 `IMAGE_CONTEXT_COST_CHARS`（默认 4000 字符的**保守代理**，宿主可调）计入。真实 token 成本取决于后端分块方式，这个值是代理不是计费器——价值是"别让图片免费占预算"。

### 2.2 后端能力探测：没声明就降级，不发后端不认的数组

新增可选能力标记 `yai_multimodal`（沿用 `yai_live_router` 的约定：类属性、不进协议强制结构）。**没声明的后端按"不支持多模态"处理**：片段自动降级成纯文本占位（"当前后端不支持多模态，模型看不到这张图"），文本块原样保留——**宁可明说缺资料，也不静默丢**。

### 2.3 宿主侧解析器样板：`examples/host_k_multimodal/`

多模态最难的不是"能塞图片"，而是**"资源引用"归谁解析**。样例给了明确口径：

| 谁 | 负责什么 |
|---|---|
| 模型 | 只能**选句柄**（`res://note/1`），不能决定自己能看到什么 |
| 宿主 | 解析句柄、判作用域、判有效期、判大小——**授权与生命周期都在宿主** |
| 内核 | 只把片段带进消息、渲染占位、计预算；**不抓取任何外部资源** |

## 三、组合工具的版本管理：可命名、可回滚、可比对

组合工具就是"一段工作流"，而工作流会改。没有版本的时候，"上周那套流程长什么样"没人答得上来。

新增 `CompositeWorkflowStore`（纯数据、标准库）：存**步骤快照**、列版本、**按位置**比对（工作流顺序敏感——"第 2 步和第 3 步换位"的影响可能远大于"改了一个参数"）、还原成可注册的 `ToolSpec`。版本号是 `ToolSpec.version`（可选字段），随能力清单跨进程走，老读者不认识这个键就当没有。

## 四、跨层对抗性证据：外部声明与模型文本都改不动治理

| 攻击面 | 结论 |
|---|---|
| spec 里的 `guidance` 文本 | 默认**进不了模型提示**（来源可能是第三方 spec，能往提示里塞指令）；即使打开，**改不动闸门判定** |
| 模型参数里的 `subject` | **不算**可信主体——主体只来自宿主的运行期上下文；没有可信主体就拒绝这次调用 |
| 模型参数里的 `approval` / `governance` | **不被采纳**——审批要求只来自注册时的声明 |
| 清单里的 `gate` | **不会被重建**——函数级闸门只能由本地宿主显式绑定 |

## 五、符号链接竞态窗口：POSIX 上关进内核层

路径校验（逐段 `lstat` + `realpath` 复核）与真正 `open` 之间有窗口：校验通过之后、打开之前把最后一段换成指向别处的链接，就能读到根目录外的内容。

现在读路径用 `O_NOFOLLOW` 打开：目标是链接时内核直接拒绝（`ELOOP`），窗口在**内核层**关闭。**平台差异如实写明**：`O_NOFOLLOW` 是 POSIX 扩展，**Windows 没有**——那边窗口只能收窄、不能根除（对应测试在 Windows 上是 skip，**不是"通过"**）。
