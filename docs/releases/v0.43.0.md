# v0.43.0 — LoCoMo 词法 vs BGE-M3

> **English summary**: v0.43.0 adds a LoCoMo retrieval comparison on the same 1,973 evaluable QA:
> lexical R@5 0.3482 / MRR 0.2927; local **bge-m3** semantic 0.5067 / 0.4081; RRF hybrid
> 0.5078 / **0.4361**. It runs offline on CPU (int8 ONNX, 8 threads: embed 96.9s, retrieve 3.2s).

v0.43.0 回答一个具体问题：**给 MemoryVault 接上 BGE-M3，LoCoMo 召回能提升多少？**

## 结果

同一份 1,973 条可评估 QA、同一套证据 id：

| 方法 | Recall@5 | Recall@10 | MRR |
|---|---:|---:|---:|
| 纯词法（`recall`） | 0.3482 | 0.4163 | 0.2927 |
| **BGE-M3 语义（余弦）** | **0.5067** | **0.6066** | 0.4081 |
| **RRF 混合** | **0.5078** | 0.6064 | **0.4361** |

分类别看：

- 时序类提升最大：R@5 0.434 → 0.690；
- 多跳：0.143 → 0.289；
- 开放域：0.139 → 0.298；
- 对抗类：语义与词法 R@5 持平（0.335），但 **RRF 混合到 0.416**，MRR 0.251 → 0.314。

## 实现

- `benchmarks/memory/locomo_embedding_bench.py`：
  - 纯词法走 `MemoryVault.recall`；语义走本地 bge-m3 ONNX int8（1024d，CLS pooling + L2）
    的余弦 top-k；混合用 RRF（k=60）；
  - 每段对话独立建库、关闭去重，与 v0.40 基线一致；
  - `--workers` 多线程编码（本机 CPU 8 线程）：embed 96.9s、retrieve 3.2s、ingest 35ms。
- `tests/test_locomo_embedding_bench.py`：余弦 / RRF / 假嵌入三例，离线、不加载模型；
  numpy 缺失时跳过。

## 升级指引

- 无 breaking：只新增基准脚本与文档；
- 运行：`uv sync --extra local-embed`，然后
  `uv run python benchmarks/memory/locomo_embedding_bench.py --download --json`；
- 模型默认找 `models/bge-m3`，或设 `EMBEDDING_MODEL_DIR`。

## 明确边界

- 这是**检索指标**，不是回答准确率；BGE-M3 只替换召回通道，LoCoMo QA 生成/判定未变；
- 语义 / 混合未接入 Agent 回答生成，仅评估召回；
- 数据集不随包分发（上游 NOASSERTION）；数字与 Mem0/Zep 的语义记忆分数不可直接比较；
- 本机 CPU 实测，非 GPU 基准。
