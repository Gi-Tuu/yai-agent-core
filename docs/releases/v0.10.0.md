# YAI Agent Core v0.10.0

> 发布日期：2026-10-14 · 范围：`v0.9.0` 之后的 17 个 PR（#43–#59）· 许可证：MIT
> 本页是 GitHub Release 正文源稿；逐条变更清单以 [`CHANGELOG.md`](https://github.com/Gi-Tuu/yai-agent-core/blob/main/CHANGELOG.md) 的 `[v0.10.0]` 小节为准。

**这一版的主线只有一件事：让内核能被安全地嵌进"已经存在"的软件。** 能力声明终于能跨进程走，运行时保障补上了两处空白，多了第二个真实模型后端，文件能力有了第 10 个契约，公网端点多了两道闸。

**没有破坏性变更**：所有新增能力默认关闭或默认无行为，`import` 方式与 v0.9.0 一致。

---

## 能力声明终于能跨进程走

- `ToolSpec.governance` 的数据部分（脱敏路径、宽口径审计提示、外部契约声明快照）现在随**语言中立清单（manifest）**一起导出与导入。把一份工具清单搬到另一个进程或另一种语言，脱敏与审计收口照样生效。
- **准入判定函数 `gate` 与 `handler` 同命：不导出，也绝不凭清单里的声明快照重建。** 外来 JSON 既不能给本机工具加上闸门，也没有通道替本机把已绑定的闸门摘掉——要恢复准入，必须由宿主在本地显式重新绑定（`from_manifest_dict` 的文档里有可直接跑的代码）。
- 清单里出现内核**不认识的治理字段时直接拒绝加载**。听起来苛刻，但静默忽略一个拼错的 `sensitives` 等于"宿主声明了脱敏、内核其实没做"，比报错危险得多。
- 顺手堵了一个真漏：组合工具分支此前会把**明文参数**写进 `TOOL_COMPOSED` 事件，声明了 `sensitive` 照样漏。现在这份对外副本按组合工具自己的声明脱敏，执行仍拿真值。

## 运行时保障补两处空白

- **工具 handler 硬超时** `AgentCore(model, tool_timeout=10)`。此前模型侧有硬超时、工具侧一直裸着：一个不返回的外部调用能把整轮任务吊住。异步 handler 是**真取消**；同步 handler 丢进线程后杀不掉，所以话术分开写——"无法中断、可能仍在后台产生副作用，重试前先确认状态"，免得模型原样重打同一个调用。默认 `None`，行为与旧版逐字节一致。
- **`await core.aclose()`**：内核第一次有了统一收尾入口。规则是"谁创建谁负责关"——默认只关本实例自建的资源，宿主传进来的 model / memory / discovery / sandbox / channel 一个都不碰（多实例共享同一个无状态模型是官方推荐的并发用法）。幂等，可以放进 `finally`。

## 第二个真实模型后端

- **Anthropic 消息接口**（可选 `[anthropic]` extra）。`ModelProvider` 契约与内核零改动，差异全在适配器里翻译：`system` 走顶层参数、`max_tokens` 必填、assistant 的 `tool_calls` 译成 `tool_use` 块、`role:"tool"` 的结果译成 **user 消息里的 `tool_result` 块**并合并相邻同角色。后端不给 usage 时保持 `None`——内核不臆造 token 数。
- 不做流式、不做多模态输入（等消息层 `parts`）、不做厂商专有扩展。

## 第 10 个 SPI：文件资源

- 让 Agent 能读写文件，同时把可达范围钉死在一个根目录内。内核只定义**契约与纯路径策略**（零 IO），真正碰磁盘的实现在电池层。
- 两道路径闸：先拒非法形状（上跳、绝对路径与 UNC、盘符与数据流冒号、Windows 保留名、控制字符、超深超长），再逐段拦符号链接与重解析点（Windows 没有 `O_NOFOLLOW`，这一道必须自己走），最后对 `realpath` 做归属复核。
- 写盘口径：原子替换、独占创建、乐观并发（`file_patch` 必须带 `expected_sha256`）、超限**报错而不是截断**——半截内容看起来是完整的，会让模型基于它继续判断。

## 外部能力契约（ACC）与能力闸

- 新增可选兼容层：读懂外部生态给一个操作贴的风险 / 审批 / 审计声明，并把它接进每一次调用。上游 **26 条一致性向量逐字节入库**并在测试中校验哈希。
- **能力闸只有一个方向：外部声明只能把闸门往上抬**（ALLOW → 人工确认），宿主的 DENY 永远优先——契约不能替宿主放行。主体身份由宿主注入并逐次透传，**不沿用上一位的身份**。
- 对外口径只有一句：*Implements the ACC v1 OpenAPI Binding Parser Profile*。不写"ACC certified"（规范明令禁止），也把未实现的部分列成在册限制而不是含糊带过。

## 两道新闸

- **限流全局兜底** `global_per_minute`：每 IP 维度有盲区——一万个赞不同 IP 各发三次，`per_minute=30` 一次都不会触发，但每次都是真金白银的模型调用。现在可加一道跨来源总闸（默认关闭）。它是**本进程内**的总数，不是分布式限流。
- **沙箱 AST 静态闸门失败关闭**：600 段属性链能被解析器接受却会撑爆遍历递归，异常原本会穿透闸门。现在深嵌套显式拒绝——宁可误拒不可误放，并加了持续模糊测试 target 盯住它。

## 升级指引

| 你现在需要做什么 | |
|---|---|
| 什么都不做 | 直接升级即可，无破坏性变更、无数据迁移 |
| 想让不返回的工具别吊死整轮 | `AgentCore(model, tool_timeout=10)` |
| 想让资源随进程退出收干净 | `await core.aclose()` 放进 `finally` |
| 从清单导入了带契约声明的工具、想让准入生效 | 本地重新绑定 `gate`（文档有代码） |
| 公网端点怕被"多来源各刷一点"刷爆 | 设 `YAI_RATE_LIMIT_GLOBAL_PER_MINUTE` |

## 这一版的数字

- 内核 **92 个源文件 / 13 439 行**，`dependencies = []` 仍然为空（第三方只进可选 extras 并懒加载）
- **10 个可替换 SPI 契约**、**19 类结构化事件**（单一事件出口，禁止静默决策）
- **1 248 项自动化测试通过 / 5 项环境跳过**，行覆盖率 **96%**（CI 硬门禁 90），全部离线、不需要 API Key
- CI：Linux py3.11 / 3.12 / 3.13 + Windows py3.13 四矩阵，CodeQL、Scorecard、4 个模糊测试 target、路由基准与端到端评测
- 路由自校准基准（本版重跑）：**末段成功率 89.6% vs 规则基线 73.3%（+16pp）**，Oracle 100%
- 8 个可运行示例宿主 + 一个原生桌面产品壳

## 诚实边界（不写进卖点的那些）

- 不做 MCP Server、不做多智能体、不内置代码执行器、不内置界面、不做向量长期记忆。
- 未声明的参数**不会**被脱敏——内核不按字段名猜"这像不像密钥"，猜出来的东西不能当安全承诺。
- 同步工具的超时是"给模型的止损"，不是进程级立即脱身。
- ACC 兼容层只覆盖声明解析与 OpenAPI 绑定；`timeout_ms` / `rate_limit` 尚未映射到执行器。
- 单人项目，社区数据如实：Star 个位数、外部贡献者 0。

## 安装

```bash
pip install yai-agent-core            # PyPI（本版本发布后即为 0.10.0）
pip install "yai-agent-core[llm]"     # 加 OpenAI 兼容后端
pip install "yai-agent-core[anthropic]"
uv add yai-agent-core
```

每个发布产物带 SLSA 构建证明、cosign keyless 签名与校验和；构建与发布由 `publish.yml` 在 tag 推送时自动完成。
