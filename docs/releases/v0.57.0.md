# v0.57.0 — sidecar / composite 收尾

> **English summary**: v0.57.0 fixes the sidecar's unbounded cleanup path when a task swallows
> cancellation (uses `asyncio.wait` with a hard timeout and returns a degraded shutdown result),
> and completes the composite timeout audit trail with an in-flight `TOOL_CALL` event.

v0.57.0 清理上一轮剩余的两个 P2：sidecar 取消收尾与 composite 在途审计。

## 1. Sidecar 有界收尾

问题：`asyncio.timeout` / `wait_for` 在等待“取消完成”时，如果任务吞掉 `CancelledError`
并继续运行，超时本身也会一直等下去，shutdown 仍然无界。

修复：

- `task.cancel()` 后用 `asyncio.wait({task}, timeout=2.0)`，只等“完成或超时”，
  不等待取消握手；
- 超时返回 `{"stopped": True, "degraded": "active_run_still_running"}`；
- **不提前清空 `_active_run`、不关闭 core/bridge**，避免从仍在运行的任务脚下抽走资源；
- 任务最终完成时由 `_execute_run.finally` 自行清理。

## 2. Composite 在途 TOOL_CALL

外层 deadline 打断在途步骤时，现在审计流里同时有：

```json
{"type":"TOOL_CALL","tool":"slow","arguments":{...},"call_id":"...","composite_step":1,"timed_out":true}
{"type":"TOOL_RESULT","tool":"slow","ok":false,"status":"unknown","timed_out":true,"step_index":1}
```

不再只有一句“组合超时”；参数经过该步骤的 sensitive 规则脱敏。

## 3. 验证

- 全量门禁：2,550 项 / 2,545 passed / 5 skipped / 92.93%；
- 新增 sidecar 吞取消的 degraded 回归、composite 在途 TOOL_CALL 断言。

## 4. 边界

- Sidecar 超时后任务仍可能继续运行；进程退出时 transport 的 SIGTERM 是最终兜底。
- Composite 在途步骤只有 TOOL_CALL + unknown 结果，不生成完整执行收据；
  需要收据的业务应在工具内部自行持久化。
