# v0.27.1 — 桌面进程白名单收紧

v0.27.1 是安全补丁版，只做一件事：把 Windows 桌面执行器的进程白名单从"PID 前缀匹配"
收紧为**精确身份**，并补上宿主更该用的两种身份声明（映像名 / 完整路径）。

## 重点

- **PID 精确匹配**：`DesktopPolicy.allowed_processes` 不再做前缀匹配——`123` 不再放行
  `1234` / `1230`。旧语义在 PID 复用后会误把别的进程窗口当成目标，这次直接关掉。
- **新增两种进程身份**：`allowed_process_names`（如 `notepad.exe`，大小写不敏感）与
  `allowed_process_paths`（完整路径，大小写不敏感、`/` 与 `\` 等价）；与 PID 白名单是
  "或"关系。`DesktopPolicy.secure(...)` 接受三者任一。
- **标题不再算安全边界**：`secure()` 拒绝"只有窗口标题"的配置；直接构造数据类时标题仍可
  作附加过滤，但显式传入无进程身份的 policy 现在也会发 `DesktopSecurityWarning`
  （v0.27.0 只在完全没传 policy 时告警）。
- **进程映像随观察返回**：`WindowInfo` 新增 `process_name` / `process_path`，pywinauto
  后端用 `QueryFullProcessImageNameW` 填充，取不到时降级为空串；`to_public()` 分别截断到
  120 / 300 字符，被禁窗口的进程信息不会进入模型上下文。

## 升级指引（有 breaking 行为）

- 如果宿主用的是 `DesktopPolicy.secure(["12"])` 这类**前缀**语义（用短前缀放行一段 PID）：
  升级后会全部拒绝。请改成精确 PID，或改用 `allowed_process_names` /
  `allowed_process_paths`（推荐——PID 每次重启都会变，映像名/路径更稳定）。
- 只配置了 `allowed_window_titles` 的宿主：`secure()` 现在会直接抛 `ValueError`；请补充
  至少一种进程身份。若暂时保留宽松语义，请显式接受 `DesktopSecurityWarning`。

## 验证

- 全量离线测试：2386 项收集，全绿；内核行覆盖率 93.12%（门禁 90%）。
- `scripts/check_all.py`：lint / mypy / 版本与打包守卫 / 全量测试 / 冒烟全过。
- 真机：`scripts/windows_real_apps_smoke.py` 12/12 通过（charmap.exe，精确 PID 白名单）；
  真实桌面 `list_windows()` 6/6 可见窗口取到映像名与完整路径。

## 明确边界

- 仍只验证了少量应用（`charmap.exe` + 自建 WinForms 窗口）；第三方应用、UAC/安全桌面、
  多显示器、截图与复杂 UIA Pattern 未验收。
- 浏览器侧"显式但宽松"策略目前仍不告警，与桌面侧尚未完全对称，列入后续批次。
