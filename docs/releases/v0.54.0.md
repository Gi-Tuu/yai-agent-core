# v0.54.0 — 审计剩余四项

> **English summary**: v0.54.0 closes the four remaining audit items: trusted-proxy-only XFF,
> a composite in-flight unknown event on deadline, an AgentCore reentry guard that raises instead
> of deadlocking, and sidecar terminal-notification safety when stdout is gone.

v0.54.0 清理深度审计里最后四项可靠性与安全边界问题。

## 1. X-Forwarded-For 可信代理

- 默认 **忽略 XFF**，使用 `request.client.host`；
- 只有 peer 命中 `YAI_TRUSTED_PROXIES`（逗号分隔主机/IP）时才解析 XFF，
  从右往左剥离可信代理，返回第一个非可信地址；
- 伪造 `X-Forwarded-For: 1.2.3.4` 不再能换桶绕过每 IP 限流；
- Render/Caddy 反代需显式配置可信代理。

## 2. Composite 超时 in-flight 事件

外层 deadline 落在某个步骤内时，除组合级超时结果外，补一条该步骤的：

```json
{"tool": "<step>", "ok": false, "timed_out": true, "status": "unknown", "step_index": 1}
```

审计链不再从“上一步完成”直接跳到“组合超时”，在途副作用有明确 unknown 记录。

## 3. AgentCore 重入保护

同一任务在 DONE 回调 / `Channel.emit` / 工具 handler 内再次调用
`run` / `astream` / `aclose` 时，立即抛：

```text
AgentCore 重入：不能在 DONE 回调 / Channel.emit / 工具 handler 内再次调用...
```

不再在不可重入锁上永久等待。不同任务仍按串行契约排队。

## 4. Sidecar stdout 断开

`agent/cancelled` / `agent/error` 的发送改为尽力送达：stdout 已断开（BrokenPipe/
ConnectionReset）时不再让异常逃出 `_execute_run`，`finally` 仍会清理 `_active_run`，
避免“任务已结束但 slot 永久 busy”和未取回异常噪音。

## 验证

- 全量门禁：2,542 项 / 2,537 passed / 5 skipped，覆盖率 92.99%；
- 新增 XFF 可信代理、Core 重入、Composite 在途 unknown 断言；
- 原有 A2A / Registry / MCP / Desktop / Sidecar / Federation 回归保持通过。

## 边界

- `YAI_TRUSTED_PROXIES` 只做精确 host/IP 匹配，不解析 CIDR；
- Composite 在途步骤只补终态 unknown，不补该步骤的完整 TOOL_CALL/参数预览；
- AgentCore 重入保护针对同一 asyncio 任务；不同任务仍按文档串行排队。

完整逐条变更见 [`CHANGELOG.md`](https://github.com/Gi-Tuu/yai-agent-core/blob/main/CHANGELOG.md)。
