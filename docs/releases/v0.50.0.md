# v0.50.0 — A2A OAuth 全流程 + Go CI

> **English summary**: v0.50.0 completes the A2A host adapter's OAuth surface with authorization-code
> (`authorization_url` / `exchange_code`) and device-code (`start_device_flow` / `poll_device_token`)
> flows, and adds an optional `go build` / `go vet` workflow for the Go MCP example. Registry built-in
> signatures remain pending a v0 specification field; digest pinning + the verifier hook stay in place.

v0.50.0 把 A2A 认证补全到三种流程，并给 Go 示例加上可选的编译 CI。

## 1. A2A authorization-code / device-code

- `A2AOAuth2AuthorizationCode`：
  - `authorization_url(state)` 生成授权 URL；
  - `exchange_code(code)` 用回调 code 换 token；
- `A2AOAuth2DeviceCode`：
  - `start_device_flow()` 拿 `device_code` / `user_code` / `verification_uri`；
  - `poll_device_token(...)` 轮询，处理 `authorization_pending` / `slow_down`；
- 与 client-credentials 共享 token 缓存/Bearer 注入；浏览器、回调服务器、设备页面仍归宿主；
- 假 server 增加 `/oauth/device` 与三种 grant；**11 例离线测试**。

## 2. Go 示例可选 CI

新增 `.github/workflows/go-example.yml`：

- 仅在 `examples/host_o_go_mcp/**` 或工作流变更时触发；
- `go build ./...` + `go vet ./...`；不加入 Python 必跑门禁；
- 首次 PR 已通过（19s），示例代码编译验证。

## 3. Registry 签名

保持观察：registry v0 没有统一签名字段，继续使用 **digest pin + `verify_entry` 钩子**；
等规范给出稳定字段后再内置验签。**不伪造签名格式**。

## 验证

- 全量门禁：2,523 项 / 2,518 passed / 5 skipped，覆盖率 93.09%；
- Go job：`go build` / `go vet` 通过；
- A2A 11 例、Registry 9 例离线测试。

## 边界

- authorization-code 不含 PKCE/state 校验与回调服务器；device-code 不含设备页面；
- 只做 token 获取/缓存，用户交互由宿主完成；
- Registry 签名仍未内置（生态无标准字段）。
