# v0.52.0 — 深度审计修复

> **English summary**: v0.52.0 fixes the highest-priority findings from the deep engineering audit:
> registry host revalidation after URL-template substitution, duplicate/blank tool-call ID guards,
> desktop factory/shutdown lifecycle, honest memory durability signals and time normalization, MCP
> connect cleanup, Node sidecar cancel, browser ref stability, federation chain/manifest hygiene,
> uncommon-TLD egress detection, and a required API key in the Render blueprint.

v0.52.0 是一次**修复批次**，对应深度审计的 Batch 0/1（部分）。只改真实问题，不重构内核架构。

## 1. 安全边界

- **Registry**：变量替换后重新 `urlsplit`，复核 scheme/host/userinfo；allowlist 不可再被
  `tenant=evil.com/` 绕过。`build_config(policy=...)` 同时执行 digest pin。
- **FastAPI 部署**：Render Blueprint 自动生成 `YAI_API_KEY`；`/v1/*` 默认需要 Bearer key。
  参考 API 仍是单 core/单会话，文档明确“不是多租户服务”。
- **Egress**：裸域名识别不再依赖固定 TLD，`.xyz/.dev/.app` 等进入不可信集合；排除常见文件后缀。
- **Federation**：调用链转发加入自身 node_id，server 校验深度/环；子核 manifest 经
  `sanitize_untrusted_text` + `sanitize_schema`。
- **Browser**：生产路径只用 `current_url`，不再二次 observe 重排 `data-yai-ref`；`start()`
  幂等且失败清理。

## 2. 正确性/可靠性

- **Tool call ID**：重复 id 失败关闭（0 次执行）；空 id 合成唯一 id 并记录诊断。
- **Desktop**：工厂同步异常/`aclose` 异常都会 `_settle` 并发出 error；shutdown 幂等，
  阻塞 loop 不再 close 运行中的 loop，总等待 5s。
- **Memory**：cipher/原子写异常不再让 `dirty/persisted` 撒谎；naive/aware 时间归一化；
  单 token 去重修正；读取前 stat 指纹降低并发覆盖。
- **MCP**：`connect()` 失败关闭已打开的 Client。
- **Sidecar**：Node cancel 传 `run_id`；server 兼容无 id 并短暂等待清理；cleanup 有界。

## 3. 验证

- 全量门禁：2,536 项 / 2,531 passed / 5 skipped，覆盖率 93.01%；
- Node 客户端测试 5/5；A2A/Registry/MCP/Federation/Desktop 回归通过。

## 4. 仍未完成（明确记录）

- FastAPI 尚未按会话实例化独立 core（当前单租户；多租户需后续实现）；
- Federation subject 尚未进入签名 payload（parent 身份仍只靠 discovery token）；
- API rate limit 仍信任最左 X-Forwarded-For；
- Composite 超时 in-flight 事件、AgentCore DONE 内链式 run 死锁、sidecar
  stdout 断开终态丢失等仍未修；
- Browser/Federation 的真实外部 E2E 未补。
