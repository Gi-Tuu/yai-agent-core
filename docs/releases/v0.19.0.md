# YAI Agent Core v0.19.0

> 发布日期：2026-10-24 · 范围：`v0.18.0` 之后的 PR（#87）· 许可证：MIT
> 本页是 GitHub Release 正文源稿；逐条变更清单以 [`CHANGELOG.md`](https://github.com/Gi-Tuu/yai-agent-core/blob/main/CHANGELOG.md) 的 `[v0.19.0]` 小节为准。

**这一版把销售 CRM 的“当前选中客户”接成销售专员的现状锚，补上宿主状态在最后一个真实业务场景里的落点。**

没有破坏性变更；内核仍保持零第三方硬依赖（`dependencies = []`）。

---

## 一、网页：选中一个客户

host_e 网页客户表新增“选中”按钮，对应两个本地端点：

- `POST /api/selection`：设置/清空选中客户；客户不存在返回 404；
- `GET /api/selection`：读取当前选中摘要；
- `/api/snapshot` 与 `/api/state` 同时带上 `selected_customer`，界面刷新后能恢复选中提示。

选中态只是界面状态，**不是业务写操作**，不经过 Agent，也不改 CRM 数据；客户被删除后
自动清空，不会把过期名字继续注入。

## 二、Agent：只注入“确实选中”的客户

`Workbench._agent_state()` 只在确实有选中客户时返回状态（姓名/公司/等级/状态），
每次任务创建 Core 时注册为 `sales_selection`：

- 模型每次调用前瞬态看到当前客户，不必先问“你指的是哪位”；
- 不写历史、不进长期记忆、不参与压缩摘要；
- 未选中时完全不注入，不占上下文。

## 三、桌面销售：跨进程读取同一状态

桌面灵动岛的销售专员与本机 host_e 是两个进程。新增带令牌的
`GET /api/agent/state`，`HostECrmClient._selection()` 读取同一份选中态：

- `_selection` 保持私有——`AgentCore.auto` 只内省公开方法，状态读取不会被注册成工具；
- `_live_factory` 以 `sales_selection` 注册；
- host_e 不在线/无选中时返回空状态，provider 失败只降级，不影响任务。
