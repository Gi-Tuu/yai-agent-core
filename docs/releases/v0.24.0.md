# v0.24.0 · 把"可信"做进三个层面：成本、注入、审计

> 发布正文源稿。GitHub Release 会带 cosign 签名资产、SHA256SUMS 与
> `provenance/*.intoto.jsonl` attestation。

## 这一版是什么

八项新增，**零新增运行时依赖**（`dependencies = []` 不变），全部离线可验。
没有破坏性改动；唯一需要知道的是事件类型从 20 类变成 21 类。

## 三条主线

1. **成本：提示缓存**（`AnthropicProvider(prompt_cache=True)`）
   system 与工具清单是每轮完全相同的前缀，给它们打 `cache_control: ephemeral` 后，
   缓存命中的输入 token 按官方计价便宜一个数量级。厂商专有字段只出现在适配器里，
   `ModelProvider.achat` 契约不加参数；兼容代理不接受块状 system 时可关。

2. **注入：把工具输出当数据**
   - 回灌上下文前统一包成 `<tool_output untrusted="true">…</tool_output>`
     （Spotlighting 类防御的最小实现），事件流与收据里的原值不受影响。
   - 新增 `tests/test_injection_regression.py`：**假设模型完全照注入的话去做**，
     验证策略 DENY / 资源作用域闸 / 审批拒绝三条路径都能拦住，业务 handler 零执行。

3. **审计：可验证的收据 + 可见的拒绝**
   - 每条执行收据带 `prev_hash` / `receipt_hash`，`verify_receipt_chain()` 一次校验；
     改字段、抽条、换序都会失败。
   - `unknown`（超时 / 抛错 / 沙箱异常）可由宿主的 `postcondition` 检查确认副作用是否发生：
     确认 → 收据改判 `succeeded` 并重新接链；否认 → 保持 `unknown`。
   - **新事件 `PERMISSION_DENIED`**：被策略 / 能力闸 / 频率上限 / 审批拒绝的调用
     过去在事件流里完全看不见；现在四条路径各发一条（含脱敏后的参数），宿主可审计。

## 长会话两项

- **并行摘要压缩**：`CompactionPolicy(parallel=N)` 按轮首切段并发摘要，墙钟随段数下降，
  保留策略与消息结构不变（默认 1 = 旧行为）。
- **任务锚点**：原任务被裁剪 / 压缩后，下一次模型调用把它重新锚回 system 位；
  任务还在上下文时不重复注入。

## 升级

```bash
pip install --upgrade yai-agent-core   # 0.24.0
```

**唯一需要注意的兼容点**：事件类型从 20 类变为 **21 类**（新增 `permission_denied`）。
如果你的宿主按事件类型穷举做分支，记得补一支；忽略未知类型则无需改动。

## 本版数字

- 全量测试 **1 935 项 = 1 930 通过 + 5 跳过**（全离线）；ruff / `mypy src` 零问题
- 行覆盖率 **95.63%**（8 170 语句 / 357 未覆盖）；内核 102 个 .py / 19 202 行；测试 122 文件 / 29 778 行
- 21 类结构化事件（`tests/test_spi_surface.py` 含"无死事件"断言）

## 诚实边界

- **注入回归集测的是内核，不是模型**：模型在测试里是脚本化的"最坏情况"，
  它证明的是"就算模型被骗，内核也拦得住"，不等于真实模型不会被骗。
- **提示缓存只在 Anthropic 适配层**；OpenAI 侧缓存由厂商自动处理，本版未加参数。
- **`unknown` 的后置条件检查是宿主提供的**：宿主不给检查，收据就还是 `unknown`，
  内核不会替它猜。
- 线上 `/v1/agent/run` 鉴权仍是待决项，本版未改。
