# YAI Agent Core v0.12.0

> 发布日期：2026-10-22 · 范围：`v0.11.0` 之后的 PR（#70、#71 及本版）· 许可证：MIT
> 本页是 GitHub Release 正文源稿；逐条变更清单以 [`CHANGELOG.md`](https://github.com/Gi-Tuu/yai-agent-core/blob/main/CHANGELOG.md) 的 `[v0.12.0]` 小节为准。

**这一版的主线：把"看起来有护栏、实际没生效"的那几处补上。**

安全系统里最贵的不是"没做防护"，而是**做了但没生效**——条件永远不命中、前缀等于整个根目录、结果绕过了入参那一侧的脱敏。这些洞不会报错、不会告警，只会在一次真实的风控事件里才被发现。这一版把其中八处逐条钉死，并给每一处配了**回归测试**（写明"修复前是什么样"），另加两批新能力：外部能力契约的**执行提示**从"只解析不执行"变成真约束，消息契约加上**可选的多模态**扩展。

**没有破坏性变更**：多模态默认关闭（`parts=None`，输出与旧版逐字节相同）；治理数据不声明即无行为；`import` 方式与 v0.11.0 一致。

## 一、安全加固：八处"静默失效"

### 1. 参数级审批的数组路径曾"永远不命中"

```python
ApprovalRule(param="rows.amount", op="==", value=5000)
```

根因不是少写了个功能，而是**同一个概念写了两遍**：schema 侧会下钻数组 `items`（`rows.amount` 认得），取值侧只认对象成员（取不到）。于是路径"在 schema 里已声明"、值"取不到"，条件**静默不命中**——每一次调用都放行。护栏装在门上，钥匙插不进去，于是门一直开着。

修法不是给一侧打补丁，而是把路径语法**收敛到一处**（新增 `src/yai_core/paths.py` 作为唯一定义处）：`rows.0.amount`（显式下标）与 `rows.amount`（自动下钻）都能寻址，判定语义是 ANY（命中任一候选即命中，宁可多问一次人，不可漏问）。

### 2. 作用域闸的空字符串前缀曾等于"整个根目录可写"

`prefixes=("",)` 这一个字符的笔误，就把根目录整片变成可写区——与文档承诺的"失败关闭"直接矛盾。现在构造期就拒空串前缀并说人话，且闸本身遇空前缀一律不放行（双保险）。

### 3. 工具返回值未脱敏

入参侧（`PERMISSION_ASKED` / `channel.confirm` / `TOOL_CALL`）早就按声明脱敏，但 `TOOL_RESULT` 的 `preview` 是原文——而"把入参原样回显"是极常见的工具形状（调试工具、HTTP 客户端回显请求头）。于是密钥从**结果**这一侧绕回了事件流。现在结果侧也按声明脱敏；**返回给模型的正文仍是真值**，业务行为不变。

### 4–8. 另外四处

文件列举三处（断链符号链接不再让整次列举失败、大小改走 `lstat` 不再泄漏根目录外文件大小、截断标志不再在"恰好等于上限"时误报）、作用域闸的风险等级取更严一档、脱敏深拷贝失败时顶层必是新 dict、能力闸复核声明的 `enabled=false`。

另有一处**清单版本**的教训：治理语义与版本号脱钩时，老读者会**静默丢掉**不认识的键——跨进程导入后脱敏与审批要求全部消失，而新环境以为护栏还在。现在 `manifest_version` 升到 2，老读者拿到 v2 直接拒（失败关闭），本实现仍能读 v1 历史文件。

## 二、外部能力契约的执行提示现在真的被执行

ACC 的 `execution.timeout_ms` / `execution.rate_limit` 此前**只解析、不执行**——声明里写着"每次 10 秒""每分钟 30 次"，内核却当它不存在。现在它们翻译成内核原生的执行策略（数据），由执行器真的强制：

- **超时**与全局 `handler_timeout` **取更严的一档**（治理数据只能加严，不能放松）；
- **频率上限**用进程内滑动窗口，超限的调用**不进 handler**、也不发 `TOOL_CALL`，且在**授权之前**判定（被频率拦下的调用既不该先问人要批准，也不该留下"发生过"的审计记录）；
- ACC 侧只做"一跳"翻译，判定逻辑仍只有内核这一份。

**对抗性证据**：工具参数里塞 `timeout_ms` / `rate_limit` / `governance` **改不动**任何治理结论——治理只来自注册时挂在工具上的声明，参数是模型产物。

## 三、多模态消息契约（可选扩展）

```python
from yai_core import ChatMessage, ImagePart, TextPart

message = ChatMessage(
    role="user",
    content="这张图里有什么？",
    parts=[TextPart(text="补充：这是测试消息"), ImagePart(data=...base64...)],
)
```

- **默认 None = 纯文本消息**，`to_llm_dict()` 输出与旧版逐字节相同（有测试钉住），老宿主零改动。
- **图片有两条路径**：内联 base64（模型**真能看见**）与宿主签发的引用（渲染成"明说模型看不到"的占位，**绝不静默丢图**——模型在缺资料时照常回答，看起来成功、其实答错）。`ResourcePart` 同理：内核不替宿主取任何外部资源。
- **内联图片有硬上限**（5 MB）：图片整块进模型请求，超大载荷既烧钱又可能把请求撑爆。
- **落盘只存引用与元数据，不存图片字节**（schema v2→v3，迁移逐级进行）：历史长期驻留，不该塞进一堆没人看得懂的二进制。代价是读回的图片没有内联数据、渲染成"看不到"的占位——取舍写在脸上。
- 降级与摘要不丢信息：`parts_to_text()` 供不支持多模态的模型与上下文摘要使用（摘要器是纯文本模型，图片引用若被丢掉，"用户发来截图，结论是…"这条事实会凭空消失）。

`scripts/check_multimodal_wire.py` 可离线打印内核会发出的**确切请求体**（不需要 Key），给了 Key 可 `--live` 真机核对一次。

## 四、三处治理语义收紧

- **外来清单的审批条件路径在导入期就与 `input_schema` 交叉校验**：拼错的参数（如 `totl` 其实是 `amount`）此前能顺利导入，随后每次调用都被判"参数不合法"，工具 100% 不可用——而错误发生在别的进程里，排查成本极高。
- **"要求可信主体"不再在注册期隐藏能力**：主体是宿主在**运行期**注入的，注册期无从知道这次运行会不会有主体；用静态布尔提前隐藏，等于让宿主注入的主体在注册期就失效。现在照样暴露，但**没有可信主体的那次调用会被能力闸当场拒绝**。
- **ACC 声明里的 `guidance` 默认不再进入给模型看的工具描述**：guidance 的来源是 OpenAPI 描述，而描述常来自第三方 API——一份被污染的 spec 就能借它往模型提示里塞任意指令文本。原文仍完整保留在 `ToolSpec.governance.acc` 里，宿主显式打开才喂给模型。

## 五、门禁

ruff / mypy（94 文件）/ pytest 全绿，覆盖率 **96.30%**；CI 四矩阵 + CodeQL + 模糊测试 + 路由基准 + 离线评测；**内核零第三方硬依赖**不变（`dependencies = []`）。

> 一处依赖升级：certifi 升到 2026.10.19，修掉 emSign 中间 CA 私钥泄露（**Critical / CVSS 9.1**）——该包捆绑的根证书下有 8 张被攻破私钥的中间 CA，攻击者可签发任意主机名的合法证书。它是 httpx / requests / mcp 的传递依赖。
