# v0.28.0 — 有向父子核 Phase 1（进程内）

> **English summary**: Directed federation Phase 1: parent and child cores in one process.

v0.28.0 把"产品生态里父核调用子核"从设计推成第一版可用实现：**父核多出一份子产品的能力，
子核在结构上没有反调的路径**。全部在宿主层，内核零改动。

## 重点

- **新增 `shell/federation/`（宿主层可选模块）**
  - `ChildCore`：把子产品里独立运行的 `AgentCore` 包装成"可被调用"的子核，只暴露能力清单
    与受 grant 约束的调用入口；**不持有父核任何引用**（结构性不可反调）。
  - `Federation`：父核侧注册表 —— 把子核工具子集注册成 `<prefix>__<tool>`（例：`doc__add_entry`），
    深度 ≤3、扇出、环检测、单次调用超时，子核失败以工具错误回流、不拖垮父核。
  - `CoreGrant`：绑定"哪条边、子核身份、工具子集、subject、有效期"；父核权限/审批先判，
    子核自己的策略再判（双防线、失败关闭）。
- **可跑示例**：`examples/host_m_federation/` —— ATM 父核调用文档子核写一条流水，离线零 Key。
- **文档**：ADR 0008 追加后记；`docs/guides/federation.md` 补 Phase 1 实现范围（Phase 2 协议设计保留）。

## 升级指引

- 无 breaking：新增宿主层模块，内核 `dependencies = []` 与所有公开契约不变。
- 子核不受影响：它只是一个普通 `AgentCore`，独立使用时行为完全一样。

## 验证

- 2405 项测试收集、2400 passed / 5 skipped；内核行覆盖率 93.13%（门禁 90%）。
- 新增 `tests/test_federation.py` 12 例：方向性 / 工具子集 / grant 过期与串核 / 父核策略先判 /
  子核策略拒绝 / 失败隔离 / 深度上限 / 环检测 / 重名拒绝 / 示例子进程实跑。
- 全量门禁通过；CI 四平台矩阵 + docs build 全绿。

## 明确边界（Phase 2 起）

- **仅进程内**：没有本机 IPC、发现文件、token、HMAC 签名 grant。
- 常驻子核生命周期、manifest 热更新、每 edge 配额、预算跨核聚合、跨核事务均未实现。
- 不做对等 Multi-Agent 协商；子核之间不建立通道，兄弟协作须经共同父核。

完整逐条变更见 [`CHANGELOG.md`](https://github.com/Gi-Tuu/yai-agent-core/blob/main/CHANGELOG.md)。
