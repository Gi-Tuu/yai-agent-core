# v0.46.0 — MCP Registry 发现 + A2A 定位

> **English summary**: v0.46.0 adds read-only discovery of the official MCP Registry (search
> `/v0/servers`, inspect remotes/packages, explicitly build a config with HTTPS/variable/header
> checks; no auto-install or auto-connect) and an A2A 1.0 positioning document that keeps
> agent-to-agent orchestration out of the kernel and places it at the host layer.

v0.46.0 做两件"边界"工作：把 MCP 生态的入口接进来，把 A2A 的边界写清楚。

## 1. MCP Registry 只读发现

- 新增 `yai_core.integrations.mcp.registry`：
  - `McpRegistryClient.search(query, limit=...)` 调官方 `GET /v0/servers`；
  - 解析 remotes / packages / repository / latest；描述经 `sanitize_untrusted_text` 净化；
  - `RegistryServer.build_config()` 只接受 **HTTPS + streamable-http**，显式校验 URL 变量与
    必填头；缺失直接报错，不猜默认值。
- **明确不做**：自动安装 npm/pypi/oci 包、执行 registry 命令、自动连接 server。
- 示例：`examples/host_mcp_registry/search.py sql --limit 3`，真实 registry 搜索已验证。
- 测试：`tests/test_mcp_registry.py` 4 例离线（嵌套响应、隐藏字符、变量/头、HTTP 拒绝、畸形响应）。

## 2. A2A 1.0 定位

- 新增 `docs/guides/a2a-positioning.md` / `.en.md`：
  - A2A 是 Agent↔Agent 层，与 MCP（工具）、AG-UI（界面）分层不同；
  - **A2A 不进内核**：YAI 不做 Multi-Agent / peer 发现 / A2A server；
  - 有向父子核是父产品调用子产品能力的单向组合，**不是** A2A peer-to-peer；
  - 宿主层适配器方案：A2A client 把远端 Agent 包成 `ToolSpec`，权限/预算/审计仍归内核；
  - 重访条件写清楚，避免"为了协议而协议"。

## 验证

- 全量门禁：2,505 项 / 2,500 passed / 5 skipped，覆盖率 93.15%；
- 双语配对、sdist 链接、docs 站点链接、registry 真机搜索全部通过。

## 边界

- Registry API 仍为 v0，只做只读搜索；`sse` remote 仅展示，不自动接入；
- 信任决策在宿主：registry 元数据不构成安全背书；
- A2A 只给定位与宿主层方案，不提供官方 A2A client/server 依赖。
