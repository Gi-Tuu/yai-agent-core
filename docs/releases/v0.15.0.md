# YAI Agent Core v0.15.0

> 发布日期：2026-10-24 · 范围：`v0.14.0` 之后的 PR（#77）· 许可证：MIT
> 本页是 GitHub Release 正文源稿；逐条变更清单以 [`CHANGELOG.md`](https://github.com/Gi-Tuu/yai-agent-core/blob/main/CHANGELOG.md) 的 `[v0.15.0]` 小节为准。

**这一版的主线：让模型看见宿主“此刻”的现状，同时把重放、预览与文件路径的边界再收紧，并给路由学习补上“泛化”证据。**

没有破坏性变更：不注册状态 provider 时行为与 v0.14.0 完全一致；幂等与预览的收紧只影响原本就会误判或绕过的路径。

---

## 一、宿主实时状态（现状锚）

普通软件不只有“工具动作”，还有随时变化的界面与业务状态：当前打开的文档、选中的客户、正在编辑的表格行。把这些写进对话历史会过期、白占预算，还可能被压缩进摘要。

新增 `AgentCore.register_state_provider(name, provider)`：

```python
core.register_state_provider(
    "workbench",
    lambda: {"selected_customer": window.current_customer.name,
             "open_tab": window.current_tab},
)
```

- **每轮重新取**：规划/执行/收尾/重规划的每次主模型调用前调用宿主回调；
  工具数超预算时的“工具名聚焦”窄调用不注入，避免白花 token；
- **只读、瞬态**：作为 `system` 块插在基础提示之后、历史之前，不写入
  `Context.messages`，因此不进压缩摘要、不进长期记忆、下一轮不沿用旧值；
- **数据不是指令**：注入块明确标注来源与优先级；状态只能由宿主注册，
  模型参数、工具结果与用户消息都改不了它；
- **有界**：单 provider 默认 2000 字符、总量 4000、最多 16 个、异步 provider
  等待上限 2 秒；provider 抛错/超时/返回不可序列化值只发 `HOST_STATE_FAILED`
  诊断并跳过，任务继续；
- **可观测**：状态变化或首次注入时发 `HOST_STATE` 事件，载荷只含 provider 名、
  字符数、截断标记与指纹，**不含状态内容**；
- **多租户边界**：provider 无参，状态属于这个 `AgentCore` 实例；多用户场景应
  每会话一个 core，避免状态串号。

## 二、执行治理加固

- **预览 token 收窄**：host_e 不再哈希整个 CRM 快照，而是按工具圈定依据
  （目标客户及其跟进、目标商机、待办集合、订单表决定的新订单号等）。审批卡
  开着时去隔壁补一条待办，不会再让这次审批误判 `preview_stale`；同一目标的
  变化仍会失效。
- **幂等重放不再绕过权限收紧**：重放前仍做一次策略判定，当前策略为 DENY 时
  拒绝；缓存条目绑定参数指纹，同一个幂等键换了参数会返回 `idempotency_conflict`
  （`not_started`），而不是把上次结果当成这次的。重放本身仍不重复执行、
  不重新弹人工审批。

## 三、学习泛化证据

原来的主 benchmark 在同批任务上边学边测，末段成功率包含“已经见过这道题”的
记忆成分。新增 `python scripts/benchmark_router.py --holdout`：

- 60 条任务按策略分层切成 44 条训练 / 16 条留出；
- 只在训练集学习，**冻结参数后**在没见过的任务上评测；
- 与规则基线、Oracle 对比，并做“显著优于规则”的硬校验；
- 默认 8 seeds 结果：冻结 bandit **89.8%** vs 规则 **56.2%**，上下文覆盖 100%。

该评测已接入 CI 的 `router benchmark` job，产物与主曲线一起上传。

## 四、文件路径竞态

`O_NOFOLLOW` 只保护最后一段，父目录在校验后被换成链接仍能把读取/落盘引到
别处；Windows 连 `O_NOFOLLOW` 都没有。现在：

- 读路径在 `open` 后用句柄真实路径复核（Linux `/proc/self/fd`、macOS
  `F_GETPATH`、Windows `GetFinalPathNameByHandleW`）；
- 写路径在 `replace`/`link` 前再 `realpath` 复核一次；
- 平台取不到句柄路径时按未验证降级，不制造新的失败面，也不假装验证过；
- Windows 新增 junction 父目录替换测试，证明句柄复核在该平台确实生效。

**诚实边界**：这不是“Windows 上的内核级无竞态”，而是在没有 `O_NOFOLLOW` 的
平台上把窗口收窄并通过句柄复核发现替换；真正的强一致仍需宿主在自己的写事务里
做最终检查。

## 五、门禁

ruff / mypy（96 文件，Windows 与 `--platform linux` 两种口径）/ pytest 全绿：
**1524 passed / 5 skipped**，行覆盖率 **95.16%**；CI 四矩阵 + CodeQL + 模糊测试 +
路由主曲线与留出集评测 + 离线 Agent 评测；**内核零第三方硬依赖**不变
（`dependencies = []`）。
