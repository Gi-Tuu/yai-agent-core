# v0.22.0 · 全面体检整改批次

> 发布正文源稿。GitHub Release 会带上 cosign 签名资产（wheel/sdist 及各自 .sig/.pem/.sigstore + SHA256SUMS）。

## 三条主线

1. **给最引以为傲的那条红线，补上真正拦得住人的守门测试**
   `dependencies = []`（内核本体零第三方硬依赖）是这个项目最核心的承诺。此前它只有**一个**守卫：
   `tests/test_mcp_bridge.py` 里的 `test_no_toplevel_mcp_import_keeps_kernel_dependency_free`——
   只检查 `integrations/mcp/client.py` **一个文件**，而且整个模块顶部 `pytest.importorskip("mcp")`，
   没装 `[mcp]` extra 的环境里**整条守卫被跳过**。实测把 `import httpx` 注入
   `src/yai_core/core.py` / `tools/executor.py` 顶层，全量 1 564 项测试**全绿**，
   红线已经破了而 CI 一声不吭。
   新增 `tests/test_kernel_dependencies.py`（12 例）：用 AST 扫 `src/yai_core` 全量 102 个文件的
   **模块顶层** import（函数体内的懒加载仍被允许，那正是可选依赖的正确写法），
   并断言 `pyproject.toml` 的 `dependencies == []`；守卫自身带反证用例。
   已实测：往 `core.py` / `tools/executor.py` / `kernel/loop.py` 顶层注入第三方 import，**三处全部变红**。

2. **死事件变活：回收代码工具这件事，事件流里看得见了**
   `CODE_TOOL_RETIRED` 一直定义在 `types.py`，白皮书把它列为对外可见的 20 类事件之一，
   `examples/runner_common.py` 也有对应的消费分支——但内核**从头到尾没发过**：
   `CodeToolManager.expire_stale()` 静默注销过期代码工具，不留任何痕迹。
   现在执行器在 run 内发现代码工具已过期时，除发 `TOOL_RESULT(ok=False)` 外另发
   `CODE_TOOL_RETIRED`（`data = {name, source: "code", reason: "expired"}`），
   宿主得以区分"工具被回收"与"工具调用失败"。
   新增 `tests/test_spi_surface.py`（7 例）：十个 SPI 契约的数量与形状、
   README 清单的对应关系，以及**"每个事件类型都必须在 `src/` 里有真实发出点"**这条断言——
   同类死事件不会再悄悄长出来。

3. **发出去的包，自己得能测过**
   `pyproject.toml` 的 sdist 白名单只含 `src/yai_core` 与 `tests`，不含 `shell/`、`examples/`、
   `scripts/`、`uv.lock`、`SECURITY.zh-CN.md`——而 `tests/` 里有 21 个模块依赖它们。
   实测从解包的 sdist 跑 `pytest --collect-only`：**21 个模块收集失败**（`ModuleNotFoundError: shell.desktop.host` 等），
   只能收集到 1 276 项；`test_version_consistency.py`（读 `uv.lock`）与
   `test_security_policy_parity.py`（要 `SECURITY.zh-CN.md`）直接失败。
   顺带查出白名单被 hatchling 的 gitignore 语义击穿：无前导斜杠的 `"README.md"` 会匹配**任意层级**同名文件，
   已发布的 0.21.0 sdist 因此混进了 9 个白名单外的 README.md。
   现在所有模式改为 `/` 根锚定并补齐依赖，实测**从解包 sdist 跑全量测试 exit 0**。

## 升级

```bash
pip install --upgrade yai-agent-core   # 0.22.0
```

无新增可选依赖。`[anthropic]` 的版本约束收紧为 `>=0.40,<2`（官方 SDK 1.x→2.x 是 breaking 区间，
而本项目测试用假模块，CI 发现不了真实 SDK 的 API 漂移）——**如果你已经在用 2.x，需要先验证或反馈**。

- 本版**没有新增内核能力**，是把"实现已经比文档靠前 7 个版本"这件事掰回齐平：
  README / comparison / SECURITY / CONTRIBUTING / architecture / 白皮书的事实与措辞全部重新校准，
  讲义第 06 / 18 / 21 / 22 / 41 篇与源码重新对齐（讲义第 06 篇的系统提示词整段重写）。

  它们描述的是那一个版本，不随本版漂移。
