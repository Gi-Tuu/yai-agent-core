# v0.55.0 — 多会话安全 + Federation fail-closed

> **English summary**: v0.55.0 binds API sessions to API-key principals, adds in-flight
> refcounts so LRU never closes a running core, makes federation parent allowlists mandatory,
> keys quota per token, hardens discovery files, adds CIDR trusted proxies, and enables Mermaid
> rendering on the docs site.

v0.55.0 修复上一轮审计的 Batch 0：多会话安全边界与 Federation 默认 fail-closed。

## 1. API 多会话安全

- `ApiKeyAuth.principal()` 返回基于 Key 的稳定主体标识（哈希，不落原文）；
- session 键改为 `principal:session_id`：不同 Key 提交同一个 session_id 不再命中同一 core；
- Session 池引入 in-flight 引用计数：LRU **只回收空闲 core**；活跃请求结束后才淘汰；
- 单 core 模式仍拒绝 session_id；多会话模式仍要求 session_id 合法。

## 2. Federation fail-closed

- `ChildServer` 默认**必须**配置 `parent_tools` 父核/工具白名单；
  仅本地演示可显式 `allow_any_parent=True`；
- quota 从按 `edge` 改为按 token/服务计数，轮换 parent_id 不再重置；
- Discovery：node_id 拒绝路径穿越；临时文件 0600 创建，目录 0700（POSIX）；
- subject 仍是签名声明，不把它冒充成身份认证；真正的 parent 认证仍需逐 parent token。

## 3. 部署与文档

- `YAI_TRUSTED_PROXIES` 支持 CIDR；未配置时继续忽略 XFF；
- Render/Caddy 部署需显式配置可信代理，否则共享代理 IP 限流桶；
- `mkdocs.yml` 增加 mermaid custom fence + `docs/javascripts/mermaid.js`，AG-UI 时序图可渲染；
- demo-deployment 改为“多 session / Key 命名空间隔离”的正确描述。

## 4. 验证

- 全量门禁：2,547 项 / 2,542 passed / 5 skipped / 93.01%；
- 新增跨 Key session、活跃 session 不回收、Federation allowlist、discovery 路径穿越、
  quota 轮换等回归。

## 5. 仍未闭环

- Federation subject 仍是 capability 持有者自报的 claim；若要身份级隔离，需要 per-parent token 或外部身份。
- API Key 仍代表一个租户；不要把同一 Key 分发给互不信任用户。
- Session 工厂仍在全局锁内创建（慢工厂会串行化新会话）。
- Sidecar 超时后任务残留、composite 完整 TOOL_CALL 等 P2/P3 仍待后续。

完整逐条变更见 [`CHANGELOG.md`](https://github.com/Gi-Tuu/yai-agent-core/blob/main/CHANGELOG.md)。
