# v0.45.0 — LoCoMo 评分增强

> **English summary**: v0.45.0 adds two scoring layers over existing LoCoMo predictions, without
> regenerating answers: temporal date normalization (relative times resolved against the evidence
> session date) and an LLM judge for semantic equivalence. Answerable categories 1–4 (n=1,527):
> raw F1 0.3481 → temporal F1 0.3872, EM 0.1932 → 0.2390, judge accuracy 0.4237. Judge cost:
> 1,973 calls, ~367s at concurrency 8.

v0.45.0 不重新生成回答，只把**评分**做得更公平：相对时间归一化 + LLM judge。

## 实现

- `benchmarks/memory/locomo_e2e_judge.py`：
  - 读 `locomo_e2e_bench.py --predictions` 的 JSONL，**不重新生成回答**；
  - 时序：按证据轮次 `D<session>:<turn>` 找到 `session_N_date_time`，解析
    Yesterday / Last year / 绝对日期 / 年份 / 月年，归一后比较；非时间答案保留原始 F1/EM；
  - judge：同模型、prompt 带参考日期，判语义等价（YES/NO），3 次重试。
- `tests/test_locomo_e2e_judge.py`：4 例离线回归（日期解析、相对时间、时序评分、judge 解析/假 judge）。

## 代价与边界

- judge 1,973 次调用，本机并发 8 约 **367s**，0 失败（与回答生成同量级）；
- 时序归一化只覆盖可解析表达（92/1,973）；
- judge 是同一模型判分，可能偏好自己的表达风格，**不等于人工金标**；
- 两者依赖 LoCoMo 会话日期与 gold，不能跨数据集直接比较。
