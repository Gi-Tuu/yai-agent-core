# v0.58.0 — Composite 收据 + Sidecar 终止边界

> **English summary**: v0.58.0 adds an ExecutionReceipt for the in-flight composite step so the
> receipt chain remains verifiable after a deadline, and documents the honest sidecar boundary:
> Python cannot force-kill a task; only process-level SIGTERM/SIGKILL can.

v0.58.0 是最后两个审计项的收尾：composite 完整收据，以及 sidecar 强制终止的诚实边界。

## 1. Composite 在途收据

外层 deadline 打断在途步骤时，现在事件流里有：

- `TOOL_CALL`（脱敏参数、`call_id`、`composite_step`、`timed_out`）；
- `TOOL_RESULT(status="unknown")`；
- 该步骤的 `ExecutionReceipt`（`status="unknown"`）。

因此导出的收据链仍能通过 `verify_receipt_chain`，不再从「上一步完成」直接跳到
「组合超时」。

## 2. Sidecar 强制终止边界

Python 的 asyncio **没有**从任务外部强制杀死协程的 API。任务吞掉
`CancelledError` 后，唯一真正的强制终止是进程级 SIGTERM/SIGKILL。

当前行为：

- `_cleanup` 用 `asyncio.wait(..., timeout=2)` 有界等待；
- 超时返回 `degraded`，保留 core/bridge，不让任务在资源被抽走后继续；
- 宿主 transport 在 bridge 预算耗尽后对子进程 `terminate()` / `kill()`；
- 不再声称“任务已被强制结束”。

## 3. 验证

- 全量门禁：2,550 项 / 2,545 passed / 5 skipped / 92.93%；
- composite 超时测试断言 `TOOL_CALL`、unknown 结果、收据链有效。

## 4. 边界

- Composite 的 in-flight 收据是合成收据，不包含步骤完整的 `TOOL_RESULT.preview`；它只证明
  “该步骤已开始且状态 unknown”。
- Sidecar 的 degraded 是进程退出前的最后状态；真正的资源回收由 OS 进程终止完成。
