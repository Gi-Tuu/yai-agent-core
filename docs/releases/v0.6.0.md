## 新增（Added）

- **能力缺口感知（capability_missing 事件）**：LLM 路由在判断现有工具不足以完成任务时，输出 `missing_capability` 缺口描述，内核据此发出新的 `capability_missing` 事件（含任务、缺口、当前可用工具清单）。内核不再假装工具存在或盲目调用，而是显式告诉宿主"我缺什么能力"，为后续工具发现（MCP 目录 / OpenAPI 目录 / 插件市场）提供标准触发点。
  - `RouteDecision` 新增 `missing_capability: str | None` 字段。
  - 分类 JSON 契约新增第四字段，解析对 `null` / `none` / 空串 / 截断做容错（缺口描述截断 120 字）。
  - 四条不发事件的边界：规则路径、LLM 异常兜底、clarify 策略、无工具部署。
- **`llm_router="auto"`**：路由开关从布尔扩展为 `bool | "auto"`；`auto` 时按模型后端能力标记（`yai_live_router` 类属性）自动决定——真实模型后端（OpenAI 兼容）显式声明开启，离线脚本模型不声明即关闭。非法值启动即 `ValueError`。
- **能力发现最小闭环（ToolDiscovery SPI + StaticCatalog）**：第 5 个 SPI 契约。模型报出 `missing_capability` 后，内核向发现源要候选、统一去重、注册进工具表并发出 `tool_discovered` 事件，新工具在**本轮** ReAct 即可调用；发现源异常只发 `stage="tool_discovery"` 错误事件、不中断任务，"能被发现不等于被授权执行"（执行仍走权限闸）。
  - 新增 `spi/discovery.py`（`ToolDiscovery` Protocol：`discover(need, *, task, available) -> list[ToolSpec]`）。
  - 新增 `discovery/catalog.py`：`DiscoveredCandidate` + `StaticCatalog`（进程内、零依赖、显式关键词匹配、跳过已注册与同名候选）。
  - `AgentCore` / `AgentLoop` 新增 `discovery=` 参数；默认 `None` 时只发缺口事件、不动态注册，老接入方零改动。
  - 新增宿主 F（`examples/host_f_discovery/`）：离线确定性演示完整闭环，无需 API Key。
  - 新增事件类型 `tool_discovered`（枚举末尾追加）。
- **开源治理资产**：
  - `ROADMAP.md`：版本路线、设计原则与"明确不做"清单；
  - `docs/comparison.md`：与 LangChain/LangGraph、CrewAI/AutoGen、Dify、Coze 的诚实对比与选型建议（每条带来源）；
  - `.github/ISSUE_TEMPLATE/`（bug / feature）与 `PULL_REQUEST_TEMPLATE.md`；
  - `CONTRIBUTING.md` 新增"新人 30 分钟跑通"；
  - `scripts/build_competition_docx.py`：通用 markdown → Word/PDF 构建脚本（复用讲义样式，不新增 pip 依赖）。

## 变更（Changed）

- 系统提示词由"你只能通过工具操作"改为"你可以使用工具；现有工具不足以完成任务时，请明确指出缺失的能力"，并保留"不要编造工具不存在的数据"防幻觉护栏。
- 规则路由量词补丁："多少 / 几个 / 几条 / 几号 / 有没有"进入动作信号，"一共"移出计划信号（此前"一共有多少条笔记"等问题会被误判为 plan）。
- 全部示例与 Battery 的 `llm_router` 改为 `"auto"`（6 处）。
- 文档同步：`docs/walkthrough/05、06、15`、`docs/architecture.md`、`README.md`、`CONTRIBUTING.md`（测试数 125 → 197）。

## 修复（Fixed）

- 澄清循环死锁：意图不清时追问最多两轮、上下文累积合并、空回答体面收尾（该修复在 v0.5.0-hangzhou 之后、本批次前已合入，此处一并记录）。

## 兼容性（Migration）

- **默认行为不变**：`AgentCore` 的 `llm_router` 默认值仍为 `False`（纯规则），老接入方零改动；只有显式传 `"auto"` 或 `True` 才启用 LLM 路由。
- 新增字段 `RouteDecision.missing_capability` 有默认值 `None`，不破坏既有构造。
- 新增事件类型 `capability_missing`、`tool_discovered` 追加在事件枚举末尾，旧的事件消费方若按类型名过滤需注意新增值。
- 新增可选构造参数 `discovery`，默认 `None`（不动态注册工具）；仅在显式注入 `ToolDiscovery` 时才启用发现闭环。
- 内核本体仍保持 `dependencies = []`，openai / fastapi / mcp / httpx 均为可选 extra 且懒加载。
