# v0.56.0 — per-parent token + session 工厂并行

> **English summary**: v0.56.0 adds optional federation per-parent tokens (handshake carries
> `parent_token`; discovery token remains the transport credential) and per-session creation locks
> so a slow core factory no longer serializes all new sessions.

v0.56.0 完成上一轮审计的两个后续项：父核身份 token 与 session 创建并发。

## 1. Federation per-parent token

- `ChildServer(parent_tools={...}, parent_tokens={"atm": "tok-atm"})`；
- 握手必须携带 `parent_token`；共享 discovery token 仍负责传输接入；
- `LinkChild.connect(..., parent_token="tok-atm")`；
- `ManagedChild(..., parent_token="tok-atm")`；
- 未配置 `parent_tokens` 时保持旧行为（只校验共享 token + allowlist）；
- 新增回归：正确 token 通过、错误/缺失 token 被 `GrantDenied`。

边界：discovery token 仍能被同用户读取；per-parent token 把“能接入”与“是谁”分开，
但 token 的分发仍由宿主负责，不是 OAuth。

## 2. Session 工厂并行

- 每个 session 独立 `asyncio.Lock`，只在同一 session 首次创建时串行；
- 不同 session 的 `core_factory` 可并行执行；
- 回归：两个 200ms 工厂并发，wall 从 410ms 降到约 210ms。

## 3. 验证

- 全量门禁：2,549 项 / 2,544 passed / 5 skipped / 92.95%；
- 新增 per-parent token、session 工厂并行测试。

## 4. 仍未闭环

- Federation 的生存边界仍是“能读 discovery token 的同用户进程”；per-parent token 提高的是
  父核身份区分，不是跨用户隔离。
- API Key 仍代表一个租户；session 命名空间绑定 Key，但不要把同一 Key 分给互不信任用户。
- Sidecar 超时后任务残留、composite 完整 TOOL_CALL 等 P2/P3 仍在清单。
