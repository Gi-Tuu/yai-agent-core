# v0.59.0 — 巨型模块拆分（第一批）

> **English summary**: v0.59.0 is a behavior-preserving structural split: receipt contracts move
> from `types.py` to `receipts.py`, governance contracts to `governance.py`, and memory note/lock/tool
> builders out of `memory/vault.py` into focused modules. Old imports remain via re-exports.

v0.59.0 只做结构拆分，不改行为；所有旧导入路径继续可用。

## 1. 拆分结果

### `types.py` 52.8KB → 27.5KB

- `src/yai_core/receipts.py`：`ExecutionReceipt` / `verify_receipt_chain` / `ReceiptStatus`；
- `src/yai_core/governance.py`：`GateDecision` / `ApprovalPolicy` / `RateLimitHint` /
  `ToolGovernance` / 清单编解码；
- `types.py` 保留 re-export，旧 `from yai_core.types import ExecutionReceipt` 不变。

### `memory/vault.py` 73.8KB → 64.2KB

- `src/yai_core/memory/note.py`：`MemoryNote`、时间归一化、倒排索引 token；
- `src/yai_core/memory/storage_lock.py`：进程内/跨进程写锁；
- `src/yai_core/memory/tools.py`：remember/recall 工具构造；
- `src/yai_core/memory/constants.py`：`VALID_KINDS` / `DEFAULT_RECALL_K`；
- `vault.py` 继续 re-export，旧导入路径不变。

## 2. 兼容性

- 公共导入路径保持：
  - `from yai_core.types import ExecutionReceipt, ToolGovernance, ...`
  - `from yai_core.memory.vault import MemoryNote, build_memory_tools, ...`
- 只移动实现，不改变事件、收据、记忆落盘格式或行为。

## 3. 验证

- 全量门禁：2,550 项 / 2,545 passed / 5 skipped / 92.95%；
- Memory / Receipt / Execution 回归通过；
- sdist 打包测试通过（新模块随包分发）。

## 4. 下一步

- 第二批候选：`kernel/loop.py`（70KB）与 `tools/executor.py`（63KB）；
- 这两个模块耦合度高，拆分前需要先抽内部状态对象，避免只做文件搬家。
- `sidecar/native_bridge.py`（50KB）同样待评估。

完整逐条变更见 [`CHANGELOG.md`](https://github.com/Gi-Tuu/yai-agent-core/blob/main/CHANGELOG.md)。
