# v0.34.0 — 真机可信度（非阻塞 nightly）

> **English summary**: A non-blocking real-machine nightly workflow for Chromium and Windows UIA.

v0.34.0 加上**真机 nightly 回归**：每天在真实 Chromium 与 Windows 上跑一次，不参与 PR 门禁。
目标是"证据持续产生"，不是"把真机问题伪装成门禁绿灯"。内核依赖与公开契约不变。

## 重点

- **`.github/workflows/nightly-real.yml`**（每日 03:17 UTC + `workflow_dispatch`）：
  - `browser-real`（ubuntu + 真实 Chromium）：`browser_smoke.py --json` 与
    `browser_provider_task_smoke.py`；报告 + 截图进 artifact；失败即红（真实信号）；
  - `windows-desktop`（windows-latest + pywinauto）：`windows_uia_smoke.py` 与
    `windows_real_apps_smoke.py`；两步 `continue-on-error`（托管 runner 交互桌面不保证），
    结果以 artifact 为准。
- **UTF-8 修复**：托管 Windows runner 控制台是 cp1252，两脚本此前打印中文 JSON 会
  `UnicodeEncodeError`；现在脚本 `main()` 固定 UTF-8 输出，workflow 也设
  `PYTHONIOENCODING=utf-8` / `PYTHONUTF8=1`。

## 实测

- **本机（2026-11-10）**：UIA `ok=true`、charmap `12/12`、browser smoke `11 receipts`。
- **GitHub 托管 runner（run 42782702561，手动触发）**：
  - browser job：`browser-smoke.json` 11 条收据、`browser-task-e2e.json` `ok: true`，截图已上传；
  - windows job：两脚本正常跑完，但 runner **无交互桌面**，UIA 与 charmap 如实返回失败
    （artifact 记录原因），job 因 `continue-on-error` 保持绿色。这符合预期：nightly 只证明
    "能跑起来并留下证据"，本机才是 UI 真机通过的依据。

## 升级指引

- 无 breaking：纯 CI / 脚本 / 文档改动；内核依赖仍为空。

## 明确边界

- nightly 不阻塞任何 PR；失败需人工看 artifact / 日志。
- 托管 Windows runner 无交互桌面，UIA 通过与否只能在人工 Windows 环境确认。
- 真实站点多样性、CAPTCHA、UAC 提权窗口、多显示器仍未覆盖。

完整逐条变更见 [`CHANGELOG.md`](https://github.com/Gi-Tuu/yai-agent-core/blob/main/CHANGELOG.md)。
