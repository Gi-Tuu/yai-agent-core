# YAI Agent Core v0.16.0

> 发布日期：2026-10-24 · 范围：`v0.15.0` 之后的 PR（#81）· 许可证：MIT
> 本页是 GitHub Release 正文源稿；逐条变更清单以 [`CHANGELOG.md`](https://github.com/Gi-Tuu/yai-agent-core/blob/main/CHANGELOG.md) 的 `[v0.16.0]` 小节为准。

**这一版的主线：让非 Python 宿主把整个 Agent 跑起来，但不另造第二套工具协议。**

没有破坏性变更：不启动 sidecar 时内核行为与 v0.15.0 完全一致；新增能力为 opt-in，内核仍保持零第三方硬依赖（`dependencies = []`）。

## 一、为什么是“会话面”，不是“工具通道”

跨语言接入现有两条成熟路径：**MCP**（任意语言的 MCP Server）与 **OpenAPI**（任意 REST 服务）。它们解决“工具面”。

但一个完整的 Agent 还需要初始化、运行、取消、审批、澄清与事件流——这是“会话面”。如果把这些也塞进工具协议，就会变成简化版 MCP，违背项目边界。

所以 v0.16.0 把两层拆开：

| 层 | 传什么 | 用什么 |
|---|---|---|
| 工具面 | 工具声明与调用 | 宿主用 MCP / OpenAPI 暴露；内核现有 Client 接入 |
| 会话面 | 初始化 / 运行 / 取消 / 审批 / 澄清 / 事件 | `python -m yai_core.sidecar` |

协议里**没有 `tool/call`**。宿主用自己语言实现一个 MCP Server（或 REST 服务）即可复用现有工具适配器。

## 二、Sidecar 控制协议

`python -m yai_core.sidecar` 在 stdin/stdout 上使用 **NDJSON + JSON-RPC 2.0**；日志只走 stderr。

| 方法 | 方向 | 作用 |
|---|---|---|
| `initialize` | 宿主 → sidecar | 模型、MCP/OpenAPI、权限挡位、交互超时 |
| `agent/run` | 宿主 → sidecar | 启动任务，立即返回 `run_id`，事件随后流式通知 |
| `agent/cancel` | 宿主 → sidecar | 取消当前任务 |
| `ping` | 宿主 → sidecar | 存活探针 |
| `shutdown` | 宿主 → sidecar | 取消任务、关桥接、关 core |
| `agent/event` | sidecar → 宿主 | 每条 `AgentEvent`（含最终 `done`） |
| `agent/cancelled` / `agent/error` | sidecar → 宿主 | 取消与运行期异常的明确信号 |
| `approval/request` | sidecar → 宿主 | 审批卡；宿主回 `{"approved": true/false}` |
| `clarify/request` | sidecar → 宿主 | 反问；宿主回 `{"answer": "..."}` |

实现口径：

- **单进程单任务**：第二次 `agent/run` 返回 `RUN_BUSY`，与 `AgentCore` 的串行锁一致；
- **审批/澄清超时**（默认 600 秒）按拒绝/空回答处理，宿主失联不会挂死任务；
- **工具接入失败**会关闭已建 core，并回滚已拉起的 MCP/OpenAPI 桥接，不留半初始化进程；
- **运行期异常**只发 `agent/error`，进程继续服务下一个任务；
- **shutdown/EOF** 取消任务、逆序关闭桥接、`core.aclose()`。

## 三、安全与边界

- sidecar 只通过 stdio 与父进程通信，不监听网络端口；
- `mcp.command` 会拉起子进程，等价于宿主自己执行命令——不要把 sidecar 暴露给不可信调用方；
- 模型 API Key 可由 `initialize` 传入或走环境变量，不写入日志/事件；
- 工具仍由内核的权限策略、审批、schema 校验、频控与执行收据统一约束，sidecar 不绕过任何一层；
- 不做持久化/断点恢复（Checkpointer 是独立议题），不做多客户端/多任务并发。

## 四、验证

- 16 个 sidecar 离线用例：初始化、流式事件、审批放行/拒绝、澄清、取消、错误码、单任务互斥、桥接清理、stdio 子进程、真实 MCP 工具、内联 OpenAPI 注册；
- 全量：**1540 passed / 5 skipped**，行覆盖率 **94.12%**；
- ruff、mypy（101 文件，Windows 与 `--platform linux` 两种口径）全绿；
- CI：4 矩阵 + CodeQL + 模糊测试 + 路由主曲线/留出集 + 离线 Agent 评测全部通过；
- stdio 入口冒烟：`initialize` → `ping` → `shutdown` 三行 JSON 正常返回。

- 跨实例分布式限流、生产级沙箱递进、组合工具可视化编排、公网实例收口（见 `ROADMAP.md`）。
