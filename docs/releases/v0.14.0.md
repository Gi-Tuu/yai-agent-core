# YAI Agent Core v0.14.0

> 发布日期：2026-10-23 · 范围：v0.13.0 之后的本地增强 · 许可证：MIT
> 本页是 GitHub Release 正文源稿；逐条变更以 [`CHANGELOG.md`](https://github.com/Gi-Tuu/yai-agent-core/blob/main/CHANGELOG.md) 的 `[v0.14.0]` 小节为准。

**这一版的主线：把“看起来有护栏”改成“每条真实路径都受约束”，并让审批人看到宿主渲染的实际变更。**

## 一、执行约束覆盖所有路径

- 组合工具按**每个真实步骤**计入任务预算；组合自身频控在分支之前判定；工作流级
  `timeout_ms` 覆盖整条组合，超时前已完成步骤的审计事件仍保留。
- 代码工具的 `timeout_ms` 收紧传给宿主沙箱的超时；同步 handler 返回 awaitable 时，
  剩余超时额度仍然生效。
- 入参 schema 校验成为**所有调用**的共同下限，而不再只服务挂了条件审批的调用。

## 二、schema 兼容性与内省

- 泛型容器注解（`list[dict[str, Any]]`、`dict[str, int]`、`set` / `tuple` / `Literal`）
  递归生成数组、对象、枚举 schema，不再退化成 `string`。
- `anyOf` / `oneOf` / `$ref` 可能放宽取值域时跳过该子 schema，避免把合法调用误拒；
  能力体检会标“未校验”。
- OpenAPI `nullable` 归一为标准 `type: [T, "null"]`；`format: date` 整串校验，
  不放尾部垃圾。

## 三、direct 严格模式与伪调用守卫

- 新增 opt-in `strict_direct`：开启后 direct 下模型自带的结构化 `tool_calls` 不执行。
- 模型把 `<tool_call>` / `<arg_key>` / `<function_call>` 写进正文时失败关闭：
  不执行、不展示原始 XML，发 `ERROR(stage=model_protocol)` 并给出可读说明。

## 四、可信变更预览

- 新增 `ChangePreview` 与 `ToolGovernance.preview`（宿主函数，不随清单导出）。
- 审批卡展示宿主渲染的 `summary / diff / target / token`；批准后执行前重新生成并比较
  token，变了即 `preview_stale` 拒绝执行，生成失败则 `preview_failed` 失败关闭。
- host_e 新增只读 `/api/agent/preview`；桌面销售专员通过该端点复用同一套业务预览规则。
- `preview_stale` 立即终止本次任务，不再让模型继续补救、烧配额。

## 五、执行收据与进程内幂等

- `ExecutionReceipt` 随 `TOOL_RESULT` 流出：`not_started` / `succeeded` / `failed` /
  `unknown` / `partial`；`call_id` 从模型调用透传。
- 超时、同步 handler 被放弃、handler 异常、沙箱调用异常记 `unknown`；组合前几步成功、
  后续失败记 `partial`，不会误当成安全重试。
- 宿主可用 `ToolGovernance.idempotency_key` 提供稳定业务键；非空 key 的进程内缓存
  使同 key 重试不再进入 handler（`replayed=True`）。跨进程/多实例去重仍由宿主负责。

## 六、门禁与边界

全量 1487 项测试（1483 通过 / 4 环境跳过），Ruff、mypy 全绿；内核零第三方硬依赖不变。
4 个跳过仍是 Docker Linux 容器 2 项、Unix rlimit 1 项、Windows 无 `O_NOFOLLOW` 1 项。

未改变默认行为的部分：组合、多模态、执行收据、严格模式均保持 opt-in 或兼容默认；
Windows 符号链接父目录窗口仍只能收窄，不能根除。
