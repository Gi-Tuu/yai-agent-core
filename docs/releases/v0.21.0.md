# v0.21.0 · Office 文本抽取 + 星云动效对齐设计稿

> 发布正文源稿。GitHub Release 会带上 cosign 签名资产（wheel/sdist 及各自 .sig/.pem/.sigstore + SHA256SUMS）。

## 三条主线

1. **Office 文档文本抽取 Battery（`batteries/office_text.py`，新 `[office]` extra）**
   docx / xlsx / pptx 走标准库 `zipfile` + `xml.etree`（零依赖），PDF 走可选 pypdf
   （BSD-3、纯 Python、0.4 MB，懒加载）。三条安全闸有测试钉住：ZIP 白名单成员 +
   逐成员流式限量（防炸弹）、全量缓冲区拒绝 `<!DOCTYPE` / `<!ENTITY`（实体攻击定义
   通道封死）、结果截断 `…[truncated]`。边界如实声明：文本级抽取，版面/样式/公式/
   数字单元格不进文本层。讲义第 55 篇。

2. **桌面星云动效对齐设计稿**：`NebulaOrbCanvas.qml` 按 web 引擎全量移植——四色调色板、
   径向光晕、虚线旋转轨道、拖尾弧、粒子爆发与双冲击波、坍缩蓄力、冻结锁定虚线环；
   所有运动按真实 dt 积分（修正按帧推进导致降帧降速的缺陷）。实测粒子数 120→260
   对 CPU 无影响，帧率才是成本杠杆（取空闲 30fps / 工作 60fps）。

3. **测试与本地工具的安全卫生批量加固**：本地 HTTP 测试客户端收编进环回 fail-closed
   的 `tests/_local_http.py`；假凭据全部改环境注入；`crm_client` 构造期强制环回；
   提交预检脚本加官方域白名单。fuzz 预言机修正 NaN 恒等陷阱（fuzzer 实测撞出）。

## 诚实边界

- Office 抽取是文本级的：版面、样式、公式、数字单元格不在输出里；
- 沙箱 worker 的 `exec` 是产品职责（AST 闸 + 受限内建 + 子进程隔离），静态扫描器
  报告的"代码注入"为形状误报，已记录不修；
- 星云动效仅桌面壳视觉，内核无变化。
