# ADR 0008：有向父子核（Directed Federation）的边界

- 状态：Proposed（2026-11-09，待 Phase 0 评审；实现未开始）
- 关联：`docs/guides/federation.md`（协议设计稿）、`shell/employee/`（现有层级委派骨架）、
  `src/yai_core/sidecar/`（JSON-RPC 与发现文件形状）、`src/yai_core/integrations/`（manifest / MCP / OpenAPI）、
  `docs/architecture.md`（并发与多实例契约）、`docs/IMPLEMENTATION_STATUS.md`
- 关联需求：产品生态 —— n 个主产品 + m 个次产品，各自嵌入一个核并独立可用；父核有调用子核的权力，
  子核不能反向越权；父子核之间需要轻量、准确、高效的通讯。

## 背景

- 产品本身没有智能体能力，用户正常使用；嵌入核后每个产品获得一个**独立的 AgentCore**：
  自己的工具、策略、记忆、预算，互不依赖。这与内核既有的"多实例 / 多专员"契约一致。
- 生态需要的是"父产品多出一份子产品的能力"（例：ATM 系统调用文档产品里的核，把业务记录写进文档），
  而不是"所有能力汇进一个超级 Agent"。
- 仓库现状提供了三块可复用件：`shell/employee` 的层级委派（权限单调收窄、预算、并发闸）、
  能力清单 manifest 的导出/导入、sidecar 的 JSON-RPC 形状与 Bridge 的"发现文件 + token"模式。
- 仓库红线：内核**不做 Multi-Agent 编排**、不做 MCP Server。因此联邦必须落在宿主层，
  内核继续只跑单 agent 循环。

## 决策

**采用"宿主层有向联邦"：核与核之间形成 DAG，边上只有父 → 子的调用权。**

1. **位置**：实现放 `shell/federation/`（宿主层，可选模块），内核零改动、`dependencies = []` 不变；
   不新增 SPI，不新增内核事件类型（子核生命周期由宿主层事件 + 收据证据表达）。
2. **拓扑**：有向无环；一个核可同时是父与子；**默认禁止兄弟直连**，兄弟协作经共同父核路由；
   所有边由宿主显式配置，不做自动发现与自动信任。
3. **方向性由凭证缺失保证**：子核进程里没有父核的 endpoint / token，因此"子核调父核"不是被策略拒绝，
   而是**无路可走**；父核持有的 `child_grant` 只授予"调用子核声明的工具子集"。
4. **能力交换**：子核发布 capability manifest（既有格式）；父核显式选子集注册为工具，
   不把子核的全部能力默认暴露给模型。
5. **通讯协议 v1**：JSON-RPC 2.0 over NDJSON，本机 loopback（`127.0.0.1` 随机端口）+ 发现文件（0600，
   含 pid / 端口 / token / 协议版本）+ 连接级 token；协议消息形状与 sidecar 对齐。预留
   POSIX UDS / Windows 命名管道替换传输层（协议不变）。
6. **治理**：`grant`（HMAC）绑定"边 + 子核身份 + 工具子集 + subject + 失效时间"；父核侧走自己的审批策略，
   子核侧用自己的策略再判一次（双防线、默认失败关闭）；预算按树聚合下发；写操作必须带幂等键。
7. **审计连续性**：子核返回自己的执行收据摘要，父核把它并入自己的 evidence 与事件；
   **不承诺跨核事务回滚**（跨核一致性靠幂等 + 重试语义）。
8. **硬闸**：最大深度默认 3、单父扇出默认 16、环检测、超时与取消向下传播、
   子核不可用时返回 `child_unavailable` 并降级（父核不崩、写操作不盲目重试）。

## 备选与取舍

| 方案 | 结论 | 理由 |
|---|---|---|
| A. 内核级 Multi-Agent 编排 | 弃 | 违反仓库红线；会把调度、协商、失败语义塞进内核，膨胀且不可控 |
| B. 每个核都服务化成 MCP/HTTP，网状互联 | 远期仅作跨机传输 | 需 MCP Server（红线）；网状拓扑的环与权限不可控；本机开销也大 |
| C. 复用 `shell/employee` 扩展成常驻子核 | **采用** | 治理骨架现成；只需把"短命任务级"升级为"常驻可复用 + 通讯层" |
| D. 有向 DAG + 本机 IPC（本 ADR） | **采用** | 方向性可结构性保证；轻量；与现有 sidecar/Bridge 形状一致 |

## 后记

- 2026-11-09：**Phase 1（进程内）已实现** —— `shell/federation/`（`CoreGrant` / `ChildCore` /
  `Federation`）、`tests/test_federation.py`（12 例）、`examples/host_m_federation/`。
  本机 IPC（Phase 2）与 HMAC 签名 grant 仍未实现；正文决策不变。

## 后果

- 新增宿主层模块与协议文档；内核仍然单 agent、零第三方依赖。
- 安全前提：父子核运行在**同一 OS 用户**下；token + 文件权限只防同机其他进程，
  **不宣称防 root / 调试器 / 内存抓取**。
- 生态可独立演进：主/次产品升级核版本时，边上的 grant 与 manifest 子集可版本化协商。
- 文档必须始终区分两种形态：**独立可用**（子核自己跑）与**被父核调用**（能力被借用），
  不得用"父核演示成功"代替"子核独立验收"。
