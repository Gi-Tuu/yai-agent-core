## 2. 竞品对照报告

见 [`docs/competitor-openmuse-audit.md`](competitor-openmuse-audit.md)（只读源码核验）。
结论摘要：

- OpenMuse-Win = **AGPL-3.0**（不可复制代码）、Windows 应用形态、88 个测试文件但
  **没有 CI**；桌面测试是 `MagicMock` 模拟，真实浏览器测试默认 `skipif(True)`；
- 其真实优势是产品完整度（Web UI、安装包、调度、多工具），不是可嵌入内核；
- YAI 差异化：MIT + `dependencies = []` + 唯一治理链路 + 收据/验收分离 + 可选 Provider +
  可复现测试。**不追求功能数量对等**。

## 3. 架构设计与 ADR

- [ADR 0004](adr/0004-browser-provider-boundary.md)：Browser Provider / 浏览器扩展 / Bridge 的边界
  （Core 不 import 浏览器库；扩展是 Host；Bridge 不改 Sidecar 协议）。
- [ADR 0005](adr/0005-outcome-verification.md)：执行收据与任务验收分离；verifier 由宿主提供；
  验收异常只降级、不重试。
- 架构文档新增 §2.12（中英同步）：`docs/architecture.md` / `docs/architecture.en.md`。

## 8. 安全风险与未解决问题

1. **浏览器验收范围有限**：真实 Chromium / 系统 Chrome 上只完成 1 条本地表单任务；
   嵌套 frame、下载 / 上传、CAPTCHA、真实站点多样性、视觉定位与多标签页复杂场景未覆盖。
2. **扩展已把"可见性"补到可验证**：`sidepanel.html` 渲染、`openPanelOnActionClick`、
   点击失败时的标签页兜底都有脚本/静态测试；但真实鼠标点击工具栏图标 → 侧边栏出现、
   Native Messaging 注册（需写注册表）、安装包分发、Service Worker 回收仍需人工按
   `docs/browser-extension-bridge.md` 验收。
3. **Windows 桌面只完成一组冒烟**：自建 WinForms 窗口；第三方应用、复杂 Pattern、截图、
   多显示器、UAC 提权窗口未验证。
4. **Bridge 生命周期**：与一次扩展连接绑定，不提供跨进程任务恢复；断连后结果标 `unknown`。
5. **截图能力**：Desktop 后端有 `screenshot()` 契约但未暴露工具、未验证；浏览器未做视觉定位。
6. **历史文档漂移**：本轮已清扫 tracked 文档的 P0/P1 漂移（SECURITY 支持版本、白皮书版本与
   内部矛盾、architecture 行号、README 中英部署链接、openssf 自评等），并新增 SECURITY
   版本表守卫测试；本地台账 `docs/项目台账.md` 仅做增量口径修正，未整体重写。
7. **`[local-embed]` / `[windows]` / 真实浏览器测试不进 CI**：CI 仍只跑离线假后端；
   本机真机证据由维护者在发版前复跑并写回 IMPLEMENTATION_STATUS。
