# 逐行讲解 47 · 安全加固第二批：把"静默失效"的那几处补上

> 这一批不是新功能，是**审计复核**后逐条修掉的洞。共同点是同一个病：
> **"看起来有护栏，实际没有"**——条件永远不命中、前缀等于整个根目录、结果绕过了
> 入参那一侧的脱敏。安全系统里最贵的不是"没做防护"，而是**做了但没生效**。
> 讲义只讲中文（不翻译），配套回归在 `tests/test_security_regressions.py`。

## 0. 这次修了什么（八条，每条都能复现）

| # | 缺陷 | 修复前 | 修复后 |
|---|---|---|---|
| 1 | 作用域闸空前缀 | `prefixes=("",)` = 整个根目录可写 | 构造期直接报错；空前缀 = 什么都不许 |
| 2 | 审批条件的数组路径 | `rows.amount == 5000` **永远不命中** | 取值侧与 schema 侧同语义，命中 |
| 3 | 工具结果预览 | 密钥随 `TOOL_RESULT` 原样进事件流 | 按声明脱敏 / 宽口径折叠 |
| 4 | 文件列举 | 断链链接让整次列举失败；链接泄漏外部文件大小 | 断链按 0 计；大小走 `lstat` 不跟随链接 |
| 5 | 截断标志 | 恰好等于上限也报"截断" | 多取一条判定，边界不再误报 |
| 6 | 闸的风险等级 | 调用方声明的 `risk` 被默认值静默覆盖 | 取更严的一档 |
| 7 | 脱敏副本 | 深拷贝失败退回**原对象** | 顶层必是新 dict，通道改不动执行参数 |
| 8 | 能力闸 | `enabled=false` 没有兜底 | 闸层直接拒 |
| 9 | manifest 版本 | 治理语义与版本号脱钩，老读者静默丢防护 | 升 v2，老读者失败关闭 |

## 1. 最有教育意义的一条：两套路径解析器

第 2 条的根因不是"少写了一个功能"，而是**同一个概念写了两遍**：

```
schema 侧：schema_at_path("rows.amount")  → 下钻数组 items → 找 amount → 找到了 ✅
取值侧：value_at_path("rows.amount")      → 只认 dict 成员            → 取不到 ❌
```

于是审批条件 `rows.amount == 5000` 的判定过程是：

1. 路径**在 schema 里已声明** → 通过第 2 道校验（"我们认识这个参数"）；
2. 取值时**取不到** → `MISSING` → `same_json_value(MISSING, 5000)` → `False`；
3. 条件永不命中 → **每一次调用都放行**。

护栏装在门上，钥匙插不进去，于是门一直开着。而这种缺陷**不会报错、不会告警**，
只会在一次真实的风控事件里才被发现。

修法不是"给取值侧打个补丁"，而是把路径语法**收敛成一处**：

```
src/yai_core/paths.py     ← 唯一定义处（value_candidates / schema_at_path）
        ↑                    ↑
policy/approval.py      policy/redact.py      （都从这里取语义）
```

统一后的语法：

| 写法 | 含义 |
|---|---|
| `headers.authorization` | 对象成员 |
| `rows.0.amount` | 显式下标进数组 |
| `rows.amount` | 自动下钻：取每个元素上同名字段的**候选集合** |

判定语义是 **ANY**：命中任一候选即命中（宁可多问一次人，不可漏问）。

> 保留了一条窄解析器 `value_at_path`（只寻址对象成员）——它是**历史公开 API**，
> 既有测试明确钉住了它的语义（`test_acc_evaluate.py`），不能顺手改掉。
> 于是文件里同时有两个"取路径"的函数，但**审批判定只走新的那个**，
> 且窄的那个在注释里写明"审批走 candidates"——歧义必须写在代码里，不能留在脑子里。

各算子在"这次调用没给这个值"时的口径**刻意保持不变**（不放松也不收紧）：

| 算子 | 值缺失时 | 为什么 |
|---|---|---|
| `>` `>=` `<` `<=` | **拒绝**（失败关闭） | 判不出大小就是判不出，不能放行 |
| `contains` | **拒绝** | 标量里"包含"无从谈起 |
| `==` `in` `exists` | 不命中 | 没有值就没有风险值 |
| `!=` | **命中**（要问人） | "不等于期望安全值"却拿不到值，本身就可疑 |

## 2. 第 1 条：空前缀为什么最危险

作用域闸的文档承诺是"失败关闭"：

> `write=True` 而 `prefixes` 为空 = 拒绝一切写（不默认放行）

但代码里 `_in_scope(relative, "")` 写着 `return True`——**空前缀 = 整个根目录**。
于是 `prefixes=("",)` 这一个字符的笔误，就把根目录整片变成了可写区：

```python
filesystem_gate(prefixes=("",), write=True)({"path": "secrets/x.txt"})
# 修复前：reject='' → 放行
```

修法是双保险：

1. **构造期**就拒空串前缀并说人话（错配要当场暴露，不能等到运行时静默放行）；
2. `_in_scope` 遇空前缀返回 `False`（万一绕过构造，闸本身也不放行）。

> 教训："失败关闭"必须同时是**文档承诺**和**代码默认值**。两者不一致时，
> 读代码的人会按代码走，而按文档走的人会以为自己安全。

## 3. 第 3 条：入参脱敏了，结果没脱敏

治理三件套里，`sensitive` 声明的路径会同时用于 `PERMISSION_ASKED` 事件、
`channel.confirm` 入参和 `TOOL_CALL` 审计事件——**入参这一侧是干净的**。
但 `TOOL_RESULT` 事件带的是 `preview: text[:200]`，**原样**。

而"把入参原样回显"是极常见的工具形状（调试工具、HTTP 客户端回显请求头、`echo`）：

```python
def echo_token(token: str) -> dict:
    return {"token": token}          # 密钥原样回到结果
```

于是密钥从**结果**这一侧绕回了事件流与追踪 span——入参侧堵了，结果侧没堵，
等于只堵了半个口子。修法在执行器里加一个 `_event_preview()`：

- `audit_sensitive`（宽口径审计提示）→ 结果整体折叠成"已折叠 + 字符数"；
- 声明了 `sensitive` 路径且结果是对象 → 按**同一批路径**脱敏后再取前 200 字符；
- 没有声明 → 保持原样（内核不按字段名猜密钥，"未声明即不脱敏"是刻意的边界）。

**返回给模型的正文仍是真值**——脱敏只作用于对外副本，业务行为不受影响。

## 4. 第 9 条：版本号是安全语义的一部分

`manifest_version` 此前一直是 1，而 v0.10 起清单里多了 `governance` 块
（脱敏路径 / 宽口径审计 / 审批要求）。危险在于**老读者**：

```python
if data.get("manifest_version") != MANIFEST_VERSION:
    raise ValueError(...)          # 老读者只认 1
```

v1 文件带着 governance → 老读者**版本号对得上** → 继续解析 → 遇到不认识的键
**静默忽略** → 跨进程导入后，脱敏与审批要求**全部消失**，而新环境以为护栏还在。

所以治理语义必须与版本号绑定：升到 v2，老读者拿到 v2 直接拒（失败关闭），
本实现仍能读 v1（历史文件照常导入）。**"宁可不导，也不带着失效的安全语义跑。"**

## 5. 复盘：这一类缺陷怎么找

三条可复用的抓手：

1. **同一概念出现两份实现** → 一定是洞（本次：`schema_at_path` vs `value_at_path`）。
2. **文档承诺 vs 代码默认值** → 对一遍（本次：失败关闭 vs 空前缀=全域）。
3. **"对外副本"与"权威对象"** → 找出每一处拷贝，逐一确认它真的是副本
   （本次：脱敏失败退回原对象）。
