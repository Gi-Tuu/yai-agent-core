# 逐行讲解 49 · 第一层收口：把"还差点"的五处补到能上线

> 这一批不是新能力，是**把上一轮列在"第一层"（现在就能做、无需任何人点头）的五件事做完**：
> 入参校验的 schema 子集、多模态的三处落地、组合工具的版本管理、跨层对抗性证据、
> 符号链接的竞态窗口。每一处都配了回归测试。

## 1. 入参校验：schema 子集从 4 个关键字扩到 13 个

此前按绑定 schema 校验调用值只实现了 `type` / `required` / `properties` / `items`——
**结构**层面，**取值域**（枚举、范围、长度、格式）一律不看。这带来一个具体后果：
声明写 `{"amount": {"type": "number", "minimum": 100}}`，调用传 `amount=1` 照样通过
"类型对、数值离谱"的入参。

现在补上：`enum` / `pattern` / `minimum` / `maximum` / `minLength` / `maxLength` /
`minItems` / `maxItems` / `format`（只实现 `date-time` 与 `date` 两种——能可靠判定的那两种）。

三条口径：

- **`enum` 用严格 JSON 相等**：`"1" != 1`、`True != 1`。沿用同一套 `same_json_value`，
  不为了"宽容"做跨类型相等——那等于给"参数写成字符串"开一条绕过门槛的路。
- **`pattern` 用 `re.search`**（JSON Schema 语义是"部分匹配"）；**模式本身非法时跳过**
  （声明写错不该让业务操作被拦），但也不假装校验过。
- **仍未实现、记录在册**：`anyOf` / `oneOf` / `allOf` / `$ref` / `additionalProperties` /
  `exclusiveMinimum` / `exclusiveMaximum` / `multipleOf` / `uniqueItems` / `const`。
  范围是**故意有限**的：多实现几个键就多几分"看起来很严"，但没实现的键会让人误以为已经校验过。

## 2. 多模态的三处落地

### 2.1 预算口径：图片不再"不占预算"

此前上下文预算按**渲染文本长度**计——图片渲染成一句占位，长度几十个字符，于是
"塞了 50 张图"在预算上几乎免费。真实的 token 成本远高于此。

现在图片按 `IMAGE_CONTEXT_COST_CHARS`（默认 4000 字符的**保守代理**）计入，
文本片段按实际长度，资源引用按其元数据长度（很小）。宿主可调
`Context(image_cost_chars=...)`。

> 这是**代理**不是精确计费：真实成本取决于后端的图像分块方式。保守代理的价值是
> "别让图片免费占预算"，不是"精确算账"。

### 2.2 后端能力探测：没声明就降级，不发后端不认的数组

新增可选能力标记 `yai_multimodal`（沿用仓库既有的 `yai_live_router` 约定：类属性、
不进协议强制结构）。`OpenAICompatProvider` / `AnthropicProvider` / `ScriptedModel` 声明它；
**没声明的后端按"不支持多模态"处理**：片段自动降级成纯文本占位（图片 → "当前后端
不支持多模态，模型看不到这张图"），**不丢信息**（文本块原样保留）。

降级发生在 `Context.llm_messages(multimodal=...)`，执行器侧的 `_model_messages()`
按模型标记取用。

### 2.3 宿主侧解析器样板：`examples/host_k_multimodal/`

多模态最难的不是"能塞图片"，而是**"资源引用"到底归谁解析**。样例给出一条明确口径：

| 谁 | 负责什么 |
|---|---|
| 模型 | 只能**选句柄**（`res://note/1`），不能决定自己能看到什么 |
| 宿主 | 解析句柄、判作用域、判有效期、判大小——**授权与生命周期都在宿主** |
| 内核 | 只负责把片段带进消息、渲染占位、计预算；**不抓取任何外部资源** |

样板里三条可复用的边界：作用域由宿主的 `allowed_scopes` 判定（模型改不了）、
有效期由宿主自己的时钟判定（内核没有时钟真相）、路径仍走内核那套纯函数
（`normalize_relative` + `resolve_within_root`，与文件能力后端**同一套语义**）。

## 3. 组合工具的版本管理：可命名、可回滚、可比对

组合工具就是"一段工作流"，而工作流会改。没有版本的时候，"上周那套流程长什么样"
没人答得上来；想退回只能凭记忆手改。

新增 `CompositeWorkflowStore`（纯数据，标准库）：

- `save(spec, version=...)`：存**步骤快照**（不含 handler、不含运行时状态）；
- `versions(name)` / `latest(name)` / `get(name, version)`；
- `diff(name, old, new)`：按**位置**比对（增/删/改）——工作流顺序敏感，
  "第 2 步和第 3 步换位"的影响可能远大于"改了一个参数"；
- `restore(name, version)`：还原成可注册的 `ToolSpec`。

版本号是 `ToolSpec.version`（可选字段），随能力清单跨进程走；老读者不认识这个键
就当没有（向后兼容）。

## 4. 跨层对抗性证据：外部声明与模型文本都改不动治理

此前只有参数级的对抗证据（参数里塞治理字段无效）。这一版把证据补到三层：

| 攻击面 | 结论 |
|---|---|
| spec 里的 `guidance` 文本 | 默认**进不了模型提示**（来源可能是第三方 spec，能往提示里塞指令）；即使打开，**改不动闸门判定** |
| 模型参数里的 `subject` | **不算**可信主体——主体只来自宿主的运行期上下文；没有可信主体就拒绝这次调用 |
| 模型参数里的 `approval` / `governance` | **不被采纳**——审批要求只来自注册时的声明；参数里的"不用审批"不生效 |
| 清单里的 `gate` | **不会被重建**——函数级闸门只能由本地宿主显式绑定 |

## 5. 符号链接的竞态窗口：POSIX 上关在**内核层**

路径校验（逐段 `lstat` + `realpath` 复核）与真正 `open` 之间有窗口：校验通过之后、
打开之前把最后一段换成指向别处的链接，就能读到根目录外的内容。

现在读路径用 `O_NOFOLLOW` 打开（`spi/resources.py::open_no_follow`）：目标是链接时
内核直接失败（`ELOOP`），窗口在**内核层**关闭。

**平台差异（必须知道）**：`O_NOFOLLOW` 是 POSIX 扩展，**Windows 没有**——那边这个窗口
只能收窄、不能根除。两条测试分别钉住：链接**调用前就在** → 跨平台都被逐段 `lstat` 拦住；
链接**校验后才被换** → 只有 POSIX 能验（Windows 上那条被 skip，**不是"通过"**）。

## 6. 上线前复查：约束必须覆盖每一条真实路径

这一批修正来自对"声明了约束、但只在部分路径生效"的复查。每一条都有离线回归：

| 缺口 | 修正 |
|---|---|
| 组合工具在预算/频控/超时之前提前分流 | 预算按组合的**每个真实步骤**计数；频控在组合分支之前；工作流级 `timeout_ms` 覆盖整条组合，超时文案明确"已完成步骤不会回滚"，且已完成步骤的事件仍留在审计流 |
| 代码工具的声明超时没传给沙箱 | 沙箱收到 `min(code_timeout, timeout_ms)`，声明只能收紧 |
| 同步函数返回 awaitable 后绕开超时 | 剩余额度继续约束返回的 awaitable，用尽即止损 |
| schema 取值域只在有审批条件时校验 | 每次调用都校验已实现的子集；有条件审批时保留"审批闸拒绝"话术 |
| `list[dict[str, Any]]` 等泛型注解退化成 `string` | 内省递归生成 `array` / `object` / `enum`，模型按声明传数组不再被误判非法 |
| 版本快照与恢复只存步骤、且共享可变对象 | 深拷贝步骤，保存 `input_schema` 与可序列化治理；`gate` 明确不还原 |
| 工具失败、最终却声称拿到凭证仍判通过 | 新增 `failed_must_tools`，并要求凭证由**成功**结果支撑 |
| 故障切换包装提前把图片降成文字 | 按实际尝试的子后端逐次降级，视觉后端仍收内容数组 |
| 图片只计入总量、不计入裁剪/压缩 | 总量、硬裁剪、摘要选区共用 `message_cost()` |
| token 无 total 时重复累计 | 用本次增量兜底，不再把历史累计值反复相加 |

这些修正共同的判据只有一句：**声明的约束不能只对"看起来最普通"的那条路径生效。**
