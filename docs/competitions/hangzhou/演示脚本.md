# YAI 数字员工 · 初赛演示视频脚本（≤5 分钟）

> v0.4，2026-09-17：新增 **host_e 销售 CRM** 核心段（独立软件零改造嵌入 + 写权限确认 + plan 多步 + 日报交付，本地终端，约 75 秒）；host_c 陪伴段压缩为 20 秒口播带过；在线 POST 仍至多 2 次。
> v0.3（2026-09-14）口径保留：host_c/host_e 均为**本地终端运行**（在线服务只挂载 host_a）；三个在线/本地演示动作均已实测。
> 硬约束：总时长 ≤ 5:00；在线 POST 限流 30 次/分钟/IP，本脚本在线 POST **至多 2 次**；演示数据全部虚构。

## 0. 录制前置（开录前 10 分钟做完）

1. 浏览器先访问一次 https://yai-agent-core.onrender.com/health 唤醒免费实例（冷启动约 30–90 秒，波动大），确认返回 `"commit":"81729f9…"`；
2. 终端开好两个标签页：① 在线 curl（PowerShell 7 / pwsh）；② 本地演示（pwsh，已 `cd 'D:\YAI Agent Core'`，依次跑 host_e 与 host_c）；VS Code 单独开窗；
3. VS Code 备好文件标签：`examples/host_a_notes/capabilities.py`、`examples/host_e_sales_crm/crm_app.py`（与 `run_agent.py` 分屏对照）、`examples/host_c_companion/capabilities.py`、`src/yai_core/kernel/router.py`；
4. **host_e 数据重置**：先跑一次 `standalone_cli.py`，菜单选 `12` 恢复演示数据再退出，保证开场客户/订单/待办与分镜一致；
5. 关闭无关通知；录屏分辨率 1080p；浏览器缩放到 125%，终端字号 16+；
6. 录屏中不出现 `.env`、API Key、任何真实个人信息。

> 测试数字口播（v0.5，2026-09-17 晚更新）：main 已含 host_e 网页工作台与澄清修复，全量 **159 项**离线测试（X-Agent 冻结快照 81729f9 为 125 项，两者都真实，不要说混）。杭州主版口播用"**159 项离线测试、5 个示例宿主**"。
> host_e 第三段（2:45–3:30）改用**网页工作台**实拍（见 §6），终端 `run_agent.py` 降为备用；这样 §6 不额外占用时长，总时长仍 ≤5:00。

## 2. POST 预算核对（限流 30 次/分钟/IP）

- 主时间轴**在线** POST：1:20–2:15 第 1 次（笔记统计）；3:50–4:25 第 2 次（MCP）；合计在线 **2 次**，远低于阈值。
- host_e（2:15–3:30）与 host_c（3:30–3:50）均为**本地进程**，消耗本地 .env 的 DeepSeek 额度，与在线限流无关。
- host_e 录前必须重置演示数据（菜单 12）；若录制失误重拍该段，先重置再重录，保证开场一致。
- 若在线段失误重拍：POST 每分钟不超过 30 次；被限流收到 429 + `Retry-After`，等 60 秒再录。
- GET（/health、/v1/tools、部署证明）不受限流影响，可随意刷新。

## 3. 冷启动与保活预案

- 每段在线录制开始前 1 分钟先 curl 一次 /health 预热；
- 仓库已配 keepwarm 工作流（每 10 分钟自动 GET /health），评审/录制窗口实例通常是热的；
- 本地 host_e/host_c 段不依赖在线实例，可利用在线冷启动等待时间先录本地段；
- 若 POST 超 60 秒无响应：实例正在冷启动，等 1 分钟重试，不要连点。

- 不说"支持任意工具/任意软件"（无法当场演示）；说"任何能提供普通 Python 函数或普通业务对象的宿主，几十行接入"。
- 不说多智能体、RAG、向量记忆、自进化（v0.1 未做）；如被问到，答"在公开路线图中，初赛版本聚焦单内核自适应"。

- 数字只说可复现的：159 项测试（main 现状；冻结快照 81729f9 为 125 项）、四矩阵、5 个示例宿主、在线 3 个本地工具 + 3 个 MCP 工具、host_e 12 个业务工具（8 读 4 写）、冻结 commit 81729f9。

## 6. host_e 网页工作台（本地应用形态，强烈建议入镜）

`uv run python examples/host_e_sales_crm/web_app.py` 启动后访问 http://127.0.0.1:8200（桌面有"host_e 数字员工（网页工作台）"快捷方式）。
纯标准库 `http.server` + SSE，零第三方依赖。**画面叙事分两层，正好对应作品主张**：

1. 打开首先是一个完整的销售 CRM：顶部 KPI（客户数 / 订单总额 / 超期未跟进 / 未完成待办），
   客户、订单、跟进记录、待办、今日日报五个原生视图，跟进/待办还有原生录入表单——
   **不嵌入 Core 也完整可用**（数据全部来自同一个 SalesCrm 业务对象）。
2. 点右上角"AI 数字员工"才从右侧滑出抽屉：自然语言交代任务，8 个读工具自动放行，
   4 个写工具弹黄色"允许/拒绝"卡片，授权后执行，**左侧 KPI 与表格实时联动变化**
   （如默认任务后：超期 3→2 位、待办 3→4 项、周涛跟进日期刷新为今天）。
3. 抽屉可随时收起回到纯软件界面；任务可"终止"；重置会先终止卡住的任务。

- 建议放在 host_e 段（2:15–3:30），时长可给 25–35 秒：先停 2 秒展示原生 CRM，
  再开抽屉跑默认任务（查超期→写跟进→建待办→日报），两次授权卡各点一次"允许执行"，
  完成后切到"跟进记录/待办"页签展示数据落库，最后收起抽屉。
- 录前先点"重置演示数据"回到种子状态。
- 口播："这就是同一个销售软件本来的样子；嵌入内核后，它没有被改造成聊天机器人，
  而是在自己的界面里获得了一个数字员工——同一个业务对象，零改造。"
